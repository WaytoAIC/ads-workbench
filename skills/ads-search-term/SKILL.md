# ads-search-term · 搜索词读懂

搜索词是买家真正敲进去的话。广告后台操作的是投放词，预算给的是活动，三者不在一层，所以要专门有一步把搜索词读懂：它在说什么需求、花的钱值不值、该留在哪个组里。

共用规矩在 `../ads-shared/`：`分工与红线.md`（先读）、`公式与口径.md`、`输出格式.md`、`术语.md`。本 skill 的细则在 `references/规则.md`，输出模板在 `templates/输出.md`。

## 一、什么时候用，什么时候不用

用：

- 「帮我过一遍搜索词报告」
- 「哪些词该否，会不会误杀」
- 「哪些词出单不错，要不要单独拿出来」
- 「这个词算核心词还是泛词」
- 「分组明细里有几个词分错了」
- 「竞品品牌词花了不少，留还是否」
- 「同一个词在好几个活动里出现，怎么办」

不用：

- 收进精确组之后出价多少、之后怎么调：`ads-bid-budget`。这里只给起价的依据。
- 判断一个活动整体留不留：`ads-campaign-task`。
- 上架前从零建词库、定主攻词：`ads-launch`。
- 想知道转化率低是不是因为买错了词：先 `ads-diagnose`，它会把这部分转过来。

## 二、先读什么

| 读什么 | 看哪些键或列 | 用来做什么 |
|---|---|---|
| `分组规则.json` | `标签`（七个槽位的文字）、`COMP`、`OFF`、`INTENT`、`MOD`、`CORE` | 七类的名字和脚本用的词表；**标签文字以这里为准** |
| `广告闭环/输出/分组明细-近14天-请人工纠错.csv` | 每个搜索词的分组、花费、点击、订单、ACOS | 逐词明细；人可以在这张表上纠错 |
| `广告闭环/输出/数字.json` | `分组账-前14天`、`分组账-近14天`（各组花费、占比、CVR、CPC、ACOS）、`泛词加跑偏`、`同词多活动`、`头部词`、`头部词分道`、`回测`、`SP-近14天`（`CVR`） | 先看大账，再看明细 |
| `广告闭环/输出/否词清单.csv` | 广告活动、否定词、匹配方式、来由 | 这一圈脚本建议否的词 |
| `广告闭环/输出/竞品品牌词分拣表.csv` | 搜索词、点击、订单、ACOS、分拣、建议、运营已在哪些活动否过 | 竞品词四种去向 |
| `广告闭环/输出/动作清单.json` | 类型为换道否定、搜索词收割、来源组否定、竞品词降价单独跑、竞品词否定、否定 ASIN、粗规则否词、交回运营判断的条目 | 已出的动作 |
| `广告闭环/输出/AI补位.json` | `搜索词补位` | 上一次模型补的分类 |
| `广告闭环/输出/读回状态.json` | `被驳回的动作` | 哪些词人说过不否、不收 |
| `广告闭环/输出/验证器.json` | 关于否词的几项检查 | 底线有没有守住 |
| `口径.json` | `门槛.粗规则否词点击`、`判定.竞品词否定的偶然概率上限`、`门槛.搜索词收割订单`、`门槛.否定ASIN点击`、`判定.泛词跑偏花费占比警戒`、`门槛.同词多活动的活动数`、`门槛.头部词个数`、`门槛.回测点击阈值`、`门槛.分拣表最小花费占比`、`调幅.收割词缺省起价`、`调幅.竞品词单独跑最低竞价` | 判断时引用 |

页面对应：动作在「行动 · 待你决定」；分组账和回测在「原因」页。

拿不到时：

- 没有搜索词报告或没跑过：让用户先跑一圈或运行 `python3 _脚本/weekly.py --dry-run`；报告怎么导见 `数据格式.md`。
- 用户直接贴了一段搜索词让你分类：可以按 `分组规则.json` 的七类当场分，但标明「未经脚本，正则没跑」，不出否定和收割建议（没有花费和订单数）。
- 没给否定词表：脚本不知道哪些词已经否过，建议可能重复，提醒人自己核对。
- `分组规则.json` 看起来还是别的品类的词表：停下来，先请人改词表，否则整张分组账都是错的。

## 三、脚本算什么，你做什么

| 脚本算 | 你做 |
|---|---|
| 按 `分组规则.json` 的正则给每个搜索词分组 | 正则命中的不改；只补脚本交给你的「没命中」清单 |
| 各组花费、占比、转化、ACOS；泛词加跑偏合计 | 先判断「这是不是主要问题」，再决定花多少力气 |
| 回测：按粗规则当时会否掉的词，后来有多少出了单 | 用它说明误杀风险 |
| 粗规则的固定点击门槛、零单偶然概率 | 复核时再过一道动态门槛，解释为什么这个词够否、那个词还不够 |
| 收割配对（精确组新建 + 来源组否定） | 解释；检查有没有落单的 |
| 竞品词分拣（留、降价单独跑、观察、否） | 解释；指出需要人判断的 |
| 验证器：没否自家品牌词、没否出过单的词、没重复否 | 读结果；不过就不谈动作 |
| — | 读懂词的意思：它是谁在搜、想要什么 |
| — | 提纠错建议和相斥词根候选 |

## 四、判断步骤

1. **先确认词表是这个品类的。** 扫一眼 `分组规则.json` 的 `CORE` 和 `OFF`，和产品对不上就停（见第二节）。
2. **先看大账，决定力气往哪使。** 读 `分组账-近14天`：七类各占多少花费、各自的 ACOS。再读 `泛词加跑偏.占比`：
   - 低于 `判定.泛词跑偏花费占比警戒`：否词不是这个产品的主要问题。直说，别让人把一周花在清词上；重点转到核心词和属性长尾的效率，以及重复投放。
   - 高于这条线：值得清一轮，进第 6 步。
3. **补位：只补没命中的。** 正则优先，这是硬顺序：
   - 脚本按词表命中的词，分组不动。
   - 「没命中」的清单由 `_脚本/llm.py` 给：落在兜底分组（泛词那一类，什么意图词根都没命中）的搜索词，按花费从高到低取前若干个，个数上限在 `ads.config.json` 的 `llm.搜索词补位上限`。
   - 清单里的词逐个读意思，给七类之一。输出只能是 `分组规则.json` 的 `标签` 里那七个值，照抄全名，一个字都不改。
   - 拿不准的词不写，让它留在兜底分组。不硬分。
   - 七类各自怎么认，见 `references/规则.md` 第一节。
4. **觉得正则分错了：提纠错建议，不改结果。** 写清「哪个词、现在在哪类、应该在哪类、因为什么、建议在哪条正则里加或减哪个词根」。改词表和改纠错表是人的事，改完要重跑。
5. **看重复和串道。** 读 `同词多活动` 和 `头部词分道`：同一个词被 `门槛.同词多活动的活动数` 个以上活动同时买，它在每个组里都有一个出价，没人知道它值多少。对应的动作是「换道否定」：在非主干组里把它精确否掉，让它回主干组跑。这不是弃词。结构层面的判断交给 `ads-campaign-task`。
6. **否定：再过一道动态门槛。** 脚本出否定动作用的是固定点击门槛（`门槛.粗规则否词点击`、`门槛.否定ASIN点击`）和偶然概率。你复核时看三样，细则在 `references/规则.md` 第二节：
   - 点击过没过动态门槛：`max(样本.否词点击下限, floor(1 ÷ 账户转化率))`。转化率越低，要等越多点击。
   - 零单是不是偶然：`(1 − 基准转化率)^点击数` 不高于 `判定.竞品词否定的偶然概率上限`。
   - 它以前出没出过单：出过单的不否。
   三样都过才是「够否」。只过一两样的写「观察」，写明还差多少点击。脚本已经提了否定、但没过动态门槛的，在「AI 判断」里写「建议先观察」和理由，过不过由人在行动页定。再用 `回测` 提醒误杀：粗规则当时会标的词里，后来有几个出了单。
7. **否定的方式。** 默认精确否定，只挡这一个词。词组否定会挡住所有带这个词根的长尾，只有当一个词根下面多个词都够否、并且词根本身的意思就和产品相斥时才提，并标「需人确认」。自家品牌词永远不否。
8. **收割：出单的词收进精确组。** 条件：近窗口出单数过 `门槛.搜索词收割订单`、不在主干活动里、还不是精确词、不是自家品牌词和 ASIN、没被否过。动作成对出现：精确组新建这个词（起价用它自己的实际 CPC，算不出时用 `调幅.收割词缺省起价`），来源组把它精确否掉。任何一条被驳回，两条都不再提。起价之后怎么调，交给 `ads-bid-budget`。
9. **竞品品牌词：四种去向。** 读分拣表：
   - 留：出过单，ACOS 在盈亏线内。
   - 降价单独跑：出过单但 ACOS 高于盈亏线。出过单就不能否，单独建精确词，按 CPC 天花板出价（下限 `调幅.竞品词单独跑最低竞价`）。
   - 观察：零单，但样本还不够说明它不出单。
   - 否：零单且样本够。
   只在一个活动里否了、别的活动还在出单的词，脚本会「交回运营判断」：全活动补否还是撤回否定，这要人定，你把两边的数摆出来。
10. **别家商品页。** 搜索词一栏是商品编号的，是自动投放或类目定位匹配到的别家页面。点击过 `门槛.否定ASIN点击`、从没出过单、不是人明确定位的，脚本会提「否定 ASIN」。没给商品定位表时，人明确定位过的也可能被误提，提醒核对。
11. **整理相斥词根。** 从跑偏和泛词里归纳词根，按人群、材质、颜色、品牌、功能、场景分类，列成候选。它们是预先否定的来源，也是 `分组规则.json` 里 `OFF` 的补充候选。加不加由人定。
12. **找拓词方向（被问到才做）。** 核心词之外的入口通常有三类：人群词、礼物词、场景词。从属性长尾和泛词里出过单的词看有没有这类苗头。要查搜索量和趋势得花钱取数，先说清再查。拓词的目标多是低成本拿到更多入口，不是把每个词推到前排。

## 五、常见情形

**情形 1：泛词加跑偏词只占很小一块**

- 读到：`泛词加跑偏.占比` 低于 `判定.泛词跑偏花费占比警戒`。
- 判断：否词不是这个产品的主要问题。
- 怎么答：第一句就说这一点；把注意力引到核心词和属性长尾的效率、重复投放上。
- 不要：照样列一长串否词建议，让人以为清词是重点。

**情形 2：一个零单的词，点击还差一点**

- 读到：例如账户转化率约 7%，这个词 12 次点击 0 单；`门槛.粗规则否词点击` 低于 14。
- 判断：动态门槛是 floor(1 ÷ 0.07) ＝ 14 次，还差 2 次。
- 怎么答：结论「观察」；写明门槛怎么算的、还差几次、下一圈再看。
- 不要：因为「看着就不相关」提前否。

**情形 3：没命中的词里有一个像是新冒出来的别家品牌**

- 读到：脚本交来的清单里有个专有名词式的词，`COMP` 里没有它。
- 判断：多半是竞品品牌词。
- 怎么答：补位到竞品品牌那一类（用 `标签` 里的原文）；对话里说明「疑似品牌，请确认」；纠错建议里写「在 `COMP` 加上这个词根」。
- 不要：自己去改 `分组规则.json`。

**情形 4：一个词在自动投放组里出了好几单**

- 读到：近窗口订单过了 `门槛.搜索词收割订单`；来源不是主干活动；还不是精确词。
- 判断：符合收割条件。
- 怎么答：引用成对的两个动作编号（精确组新建、来源组否定）；起价是它的实际 CPC；之后怎么调交给 `ads-bid-budget`。
- 不要：只提前一半或后一半。

**情形 5：竞品词在一个活动里否了，别的活动里还在出单**

- 读到：分拣表的「运营已在这些活动否过」一栏有值，同时订单大于零。
- 判断：否定和表现矛盾，规则定不了。
- 怎么答：把否过的活动、还在出单的活动、花费、订单、ACOS 摆出来；说明两种处理各自的后果；请人定。
- 不要：替人选补否或撤回。

**情形 6：用户想把某个词根整个词组否定掉**

- 读到：这个词根下面的所有搜索词及各自的订单。
- 判断：先查有没有出过单的。有 → 不是相斥词根。没有，且多个词都过了三道闸 → 可以提。
- 怎么答：列出会被一并挡掉的词；可以提的标「需人确认」并作为清单外建议。
- 不要：不查就同意。

## 六、输出

- 按 `../ads-shared/输出格式.md`，加 `templates/输出.md` 的分组大账、否定表、收割表、竞品词表、纠错建议。
- 平时只在对话里回答。每周一圈时，你补的分类由 `_脚本/llm.py` 写进 `广告闭环/输出/AI补位.json` 的 `搜索词补位`：键是搜索词原文，值是七类标签之一。不在七类里的值会被丢弃。
- 否定、收割都是清单里的动作，引用编号，指到「行动 · 待你决定」。

## 七、不许做的

- 不改正则已经命中的分组。
- 不发明第八类，不改标签的写法。
- 不否自家品牌词，不否出过单的词，不重复否已经否过的词。
- 不凭「看着不相关」就建议否定。没过门槛的只能写观察。
- 不轻易提词组否定。
- 不在泛词加跑偏占比很低时，把清词说成重点。
- 不说「已加入否定」。
- 不未经同意去调付费工具查搜索量。

## 八、自查三句

1. 我补位的每个词，值都在 `分组规则.json` 的七个标签里吗？正则命中的我有没有动过？
2. 我建议否的每个词，点击过了动态门槛、偶然概率够低、从没出过单，这三样我都核过吗？
3. 我有没有先说清「否词是不是这个产品的主要问题」，再谈具体的词？
