# 公式与口径

公式写在这一页，阈值写在仓根 `口径.json`。这里只解释每个键是什么意思、谁在用，**不另抄一份数字**。

算数是脚本的事（`_脚本/pipeline.py` 出 `广告闭环/输出/数字.json`，`_脚本/biz.py` 出 `广告闭环/输出/经营.json`）。这一页是让你读得懂那些数是怎么来的，以及向用户解释时用哪条式子。

读不到某个键时的规矩：

- 第八节「已有的键」里的：脚本会回退到内置默认值，你照常引用脚本产物，并提醒一句「`口径.json` 里这一项缺了，用的是默认值」。
- 第九节「暂定的键」里的：`口径.json` 里已经有，但值还没最后定。读得到就用，引用时带一句「暂定值」；读不到（用的是旧的口径文件）就说「口径里没有这一项」，这条判断**只说方向，不给数**。不自己编一个数顶上。

## 一、利润

| 名称 | 公式 | 说明 |
|---|---|---|
| 定价毛利率 | （售价 − 已计入的商品经营成本）÷ 售价 | 不含广告费。成本含采购、头程、配送、佣金、仓储、破损等；哪几项计了、哪几项没计，要让人说清 |
| 广告后利润率 | 定价毛利率 − TACOS | 工作台里 `算账.当前广告后利润率` |
| 广告后利润额 | 总销售额 ×（定价毛利率 − TACOS） | 也等于（广告单 + 自然单）× 客单价 ×（定价毛利率 − TACOS） |
| 利润额的三个乘数 | 总订单 × 客单价 × 利润率 | 三个都低的产品，单调广告救不回来 |
| 盈亏线 | TACOS = 定价毛利率 时利润为零 | `数字.json` 的 `四周.盈亏线` 就是四周广告前毛利率 |

## 二、目标

| 名称 | 公式 | 说明 |
|---|---|---|
| 目标 TACOS | 定价毛利率 − 目标广告后利润率 | 目标利润率是人定的；允许阶段性亏损时它是负数，平本是 0。人没填时脚本用 `经营.默认目标广告后利润率`，并在 `算账.目标广告后利润率来源` 标「口径默认」 |
| TACOS 余量 | 目标 TACOS − 当前 TACOS | 正数＝还有空间；负数＝超了 |
| 判定 | 当前 TACOS ≤ 目标 → 在目标内；高于目标但不超过定价毛利率 → 超出目标；高于定价毛利率 → 已亏损 | 三选一，对应 `算账.判定` |
| 单品日预算 | 近 7 天日均销售额 × 目标 TACOS | 一个产品全部活动加起来的花费边界，不是某个活动的预算 |

例如：定价毛利率 40%，老板说「先留 12 个点」，目标 TACOS 就是 28%；近 7 天日均卖 1,500，单品日预算约 420。销售额变了就重算，这和「预算花完了就加」是两回事。

## 三、拆解

| 名称 | 公式 |
|---|---|
| ACOS | 广告花费 ÷ 广告销售额 ＝ CPC ÷（CVR × 客单价） |
| TACOS | 广告花费 ÷ 总销售额 ＝ ACOS × 广告销售额占比 |
| 广告销售额占比 | 广告销售额 ÷ 总销售额 |
| 广告占比上限 | 目标 TACOS ÷ ACOS（在目标 TACOS 之内，广告最多能承担多大比例的销售）；ACOS 已低于目标 TACOS 时没有上限 |
| 获单成本 | CPC ÷ CVR ＝ 广告花费 ÷ 广告订单 |
| 总获单成本 | （折扣 + 广告费）÷ 总订单 |
| 断货后等效 ACOS | ACOS ÷（1 − 将断货规格占上周件数的比例） |

三条读法：

- TACOS 不对，先看是 ACOS 动了还是广告销售额占比动了；ACOS 不对，再看 CPC、CVR、客单价哪一个动了。
- 广告销售额占比没有单独的健康线。同样的目标 TACOS，ACOS 越低，广告能承担的占比越高。例如目标 TACOS 12%：ACOS 60% 时广告最多占 20%，ACOS 24% 时可以占到 50%。
- `拆解.节点` 里「上周」是最近一周，「变化」是上周比前一周，「值」是四周合计口径（见 `拆解.变化口径`）。

## 四、订单结构测算（路径用）

| 场景 | 公式 |
|---|---|
| 目标总单拆成两块 | 广告单 ＝ 目标总单 × 广告占比上限；自然单缺口 ＝ 目标总单 − 广告单 − 现自然单 |
| 自然单不变时目标内最多买多少广告单 | 广告单上限 ＝ 现自然单 × 占比上限 ÷（1 − 占比上限）。脚本在「增单」的测算里按现 ACOS 和「ACOS 再降 `经营.示例ACOS降幅`」各算了一遍 |
| 清掉无效花费后 TACOS 最多降多少 | 无效花费 ÷ 最近两周销售额（假设销售额不变，是上限） |
| 砍掉一批广告单后的利润变化 | 少掉的销售额 × 定价毛利率 − 省下的广告费；为负才是真省 |
| 每件提价一个金额后的利润率 | 脚本在「调价」的测算里按 `经营.调价测算金额` 算；假设销量、广告费、成本都不变，价格弹性未知，是上限 |
| 重构后的利润率 | 新定价毛利率 − 新 TACOS；两个都要重估，不能只动一个 |

前提都是「广告单与自然单客单价相同」。脚本的广告单按「上周件数 × 上周广告销售额占比」近似，测算自带一句 `口径` 说明，引用时一并带上。

## 五、出价与否词

| 名称 | 公式 | 说明 |
|---|---|---|
| CPC 天花板 | 目标 ACOS × 客单价 × 该对象自己的转化率 | 点击数没过 `门槛.CPC天花板自身转化率点击`（暂定值）时，改用「有转化的词的平均转化率」做基准，并标「基准值」。脚本只在「竞品词降价单独跑」里用这条式子，下限是 `调幅.竞品词单独跑最低竞价` |
| 实际出价 | 基础竞价 × 竞价策略的浮动 ×（1 + 广告位加价） | 只看基础竞价会低估实际点击成本 |
| 动态否词门槛 | max（`门槛.粗规则否词点击`，floor（1 ÷ 账户转化率）） | 转化率越低，要攒越多点击才能说「它不出单」。脚本的粗规则用的是固定门槛；动态门槛是你复核时加的一道闸 |
| 零单偶然概率 | （1 − 基准转化率）^点击数 | 不高于 `判定.竞品词否定的偶然概率上限` 才算「样本够了」 |
| 新品测试预算 | 预估获单成本 × `新品.测试预算倍数`（暂定值） | 预算太小，测试得不出结论 |

## 六、库存

| 名称 | 公式或定义 |
|---|---|
| 可售周数 | 可售 ÷ 上周销量 |
| 将断货、两周内断货 | 可售不足一周、不足两周。这是脚本里的指标定义，不是口径里的阈值 |
| 断货规格怎么处理 | 看 `参数.json` 的 `补货到仓周数`：不超过 `判定.到仓快只降预算的周数上限` → 只降预算；不超过 `判定.到仓中等的周数上限` → 暂停可售不足一周的；再长 → 暂停可售不足两周的 |
| 冗余 | 主推、次推各自要多备的比例，见 `经营.主推库存冗余`、`经营.次推库存冗余`（暂定值） |

## 七、复盘窗口

- 改动前后各取同样天数。
- 两个窗口都去掉变更当天。
- 改动后的窗口去掉归因未满的最近几天（哪几天写在 `参数.json` 的 `归因未满`）。
- 时点：执行后第 `复盘.初查天数` 天初查，只看花费和点击有没有按预期变，不下结论；第 `复盘.决定天数` 天决定继续、调整还是停；行动卡上的观察期是 `复盘.观察天数`。
- 订单数没过 `门槛.复盘下结论订单`（暂定值）的，结论只能是「看不出来」。

## 八、已有的键

`口径.json` 里现在就有，流水线和经营核算在用。分组：`调幅`、`门槛`、`判定`、`复盘`、`经营`（另有只给技能用的暂定键和 `新品` 一组，见第九节）。比例是小数，点击和订单是近 14 天的个数。

## 九、暂定的键

`口径.json` 里已经有，值是暂定的，人还会再调。这些阈值只有技能包用，流水线不读，改它不影响动作清单。引用时带一句「暂定值」；下表的「现值」只是写这份文件时的值，以 `口径.json` 为准。

|---|---|---|---|
