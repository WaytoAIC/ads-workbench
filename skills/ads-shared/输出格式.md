# 输出格式

十个 skill 的回答都按这一页的样子出。各 skill 的 `templates/输出.md` 只在这之上加自己那几张表。

## 一、顺序：先结论，后依据

1. 第一句是结论：现在的状态、最要紧的一件事。
2. 接着是四栏表。
3. 然后是动作（如果有）。
4. 最后一行固定是「要你定的」：这次有哪几件事需要人拍板。

不写开场白，不复述用户的问题，不在结尾总结一遍。

## 二、四栏表

每个判断占一行，四栏分开写。分不开的判断，说明还没想清楚。

| 数据事实 | 规则判断 | AI 判断 | 还缺什么 |
|---|---|---|---|
| 能在脚本产物里复算的数，写明来自哪个文件哪个键 | 脚本或 `口径.json` 给出的判定，原样引用 | 你读懂之后的解释、推断、和规则不一致的地方；每条带依据，并写「什么情况下不成立」 | 缺哪份数据、去哪取；不缺就写「—」 |

写法约定：

- 数据事实只写数，不带形容词。「CPC 从 1.03 到 1.21」可以，「CPC 大幅上涨」不行。
- 规则判断写清是哪条规则：「高于盈亏线（`四周.盈亏线`）」「点击没过 `门槛.关键词降竞价点击`」。
- AI 判断里出现「可能」「大概」时，后面必须跟一句怎么验证。
- 百分比保留一位小数；金额带币种；两个时间窗口写明起止日期。
- 归因未满的那几天，凡是引用了就在数后面标「（归因未满）」。

## 三、动作表

脚本清单里已有的动作用编号引用；清单外的建议单独一张表，表头一样，编号栏写「清单外」。

| 编号 | 类型 | 广告活动 | 对象 | 现值 → 新值 | 依据 | 可执行 / 缺什么 | 为什么做 | 预期改变什么 | 多久复盘 |
|---|---|---|---|---|---|---|---|---|---|

- 「类型」用工作台的动作类型原名（见 `术语.md` 第四节），不自己起名。
- 「现值 → 新值」里的新值必须来自脚本，或能用 `公式与口径.md` 里的式子从脚本的数算出来，并在依据里写出式子。
- 「可执行 / 缺什么」只有两种写法：「可执行」，或「缺：某某，补了才能定」。
- 动作多于十条时不逐条抄：按类型汇总条数和涉及花费，只展开最要紧的三到五条，其余指到「行动 · 待你决定」。
- 表后固定一句：「以上都停在待确认，要你在行动页逐条通过或驳回。」

## 四、三问

任何一个动作、任何一条建议，都要答得出这三句。答不出的不提。

| 问 | 好的回答长什么样 |
|---|---|
| 为什么做 | 指向一个具体限制或任务，而不是「优化一下」。例如：这个词出过 6 单，却一直在词组组里和别的词共用出价 |
| 预期改变什么 | 一个能读回的数和方向。例如：这个词的 CPC 降下来，单数不掉 |
| 多久复盘 | 一个日期或天数，加上「看哪个数算有效、哪个数算无效」。天数取 `口径.json` 的 `复盘.观察天数` 或 `复盘.初查天数`、`复盘.决定天数` |

三问写在动作表的后三列；决策表里对应「执行方案」「验证标准」「复盘时间」三栏。

## 五、决策表九栏

每个链接一张。前三栏是现状，中间三栏是打算，后三栏是怎么收场。

| 栏 | 写什么 | 谁写 |
|---|---|---|
| 当前状态 | 阶段、季节属性、销量、售价、定价毛利率、TACOS、ACOS、广告销售额占比 | 脚本 |
| 首要目标 | 增单、降 TACOS、调价、还是重构盈利方式；目标值 | **人定**（你可以把选项摆出来，不替人填） |
| 核心限制 | 七类里的一个，带依据 | 脚本判定，你写一句话解释 |
| 选择方向 | 四条路径里的一条，以及路径下的具体抓手 | 你给建议和理由，人选 |
| 执行方案 | 具体到搜索词、变体、广告活动、价格或预算的动作 | 你起草，引用动作编号 |
| 投入边界 | 预算上限、测试范围、能承受的阶段损失 | 你在脚本的边界上补测试范围，人确认能承受的损失 |
| 验证标准 | 哪个数变成什么样才算有效 | 你起草 |
| 复盘时间 | 何时初查、何时决定继续、调整或停止 | 你起草 |
| 后续选择 | 有效怎么放大、无效怎么撤回、撤回后换哪条路 | 你起草 |

脚本在 `决策表` 里已经给九栏各出了一句骨架，是按 `路径.脚本建议` 写的，首要目标栏写着「人定」。你的工作是在骨架上细化：把执行方案落到具体对象和动作编号，把验证标准写成到日子能对着数判断的话；骨架里的数不改。人选的路径和脚本建议不同时，后六栏按人选的重写。

人没定首要目标时，这一栏写「（待你定）」，后面六栏按「如果选某某」分情况写，最多写两种。

## 六、落盘还是只回答

- 平时被问到：只在对话里回答，不写任何文件。
- 每周一圈（`_脚本/weekly.py`）：模型输出由 `_脚本/llm.py` 校验后写进 `广告闭环/输出/AI补位.json`。各键归谁：

| 键 | 归哪个 skill |
|---|---|
| `核心限制一句话` | ads-diagnose |
| `路径建议`、`决策表草稿` | ads-path-decision |
| `任务标签` | ads-campaign-task |
| `搜索词补位` | ads-search-term |
| `周报草稿` | ads-weekly-review |

- 落盘的内容只有文字和枚举，不带新数字：引用数字只能从给你的材料里原样照抄，不心算新的百分比和金额；出现材料里没有的数，那一项整个丢弃。
- 枚举值不在允许集合里的丢弃。丢过东西，`状态` 记 `partial`。
- 依据不够时写「证据不足」，不猜；推断前面写「推断：」。
- 长度：核心限制一句话不超过 60 个字；周报草稿不超过 400 个字，分三个小节，标题固定为「这周结论」「要你拍板」「下周看什么」。
- 没接模型时这个文件的 `状态` 是 `skipped`：照常用脚本产物回答，告诉用户「模型补位这一圈没跑」。

## 七、语气

- 用运营听得懂的话。说「同一个词被三个活动同时买」，不说「存在流量内耗」。
- 一句话只说一件事。
- 不夸、不吓。数据支持到哪，话就说到哪。
