# ads-bid-budget · 出价、预算、广告位

这是经营链的最后一环：前面已经有了目标、限制和每条广告的任务，这里才决定「动多少」。出价和预算是手段，判断它们调得对不对，看的是订单有没有丢、成本有没有降、利润有没有变好。

共用规矩在 `../ads-shared/`：`分工与红线.md`（先读）、`公式与口径.md`、`输出格式.md`、`术语.md`。本 skill 的细则在 `references/规则.md`，输出模板在 `templates/输出.md`。

## 一、什么时候用，什么时候不用

用：

- 「这个词现在出 1.2，合适吗」
- 「CPC 一直涨，怎么往下压」
- 「这几条降竞价的动作，为什么是这个数」
- 「预算每天下午就花完，要不要加」
- 「整个产品一天该给多少预算，现在各活动加起来够不够」
- 「搜索顶部加价 50%，值不值」
- 「竞价策略用固定还是只降低」

不用：

- 还没有目标 TACOS 和目标 ACOS：先 `ads-profit-target`。没有目标算不出天花板。
- 不知道这条广告是干什么的：先 `ads-campaign-task`。同样的 ACOS，任务不同动作相反。
- 该否还是该收：`ads-search-term`。
- 产品层的总预算边界怎么定：`ads-profit-target`（这里引用它的结果）。
- 新品头几周的起步出价和测试预算：`ads-launch`。
- 旺季要不要整体加价：`ads-variant-season`。

拿不到时：

- 没跑过：让用户先跑一圈或运行 `python3 _脚本/weekly.py --dry-run`。
- 没给关键词竞价表：不知道现在出多少，出不了关键词的降价、提价、暂停。只能给天花板，说「现价请到后台核对」。要补的表见 `数据格式.md`。
- 没给活动预算：预算上调、下调都出不了，只能提醒补数。
- 没给商品定位表：ASIN、类目、自动四组的调整出不了。
- 没有广告位报表：广告位加价只标缺数据，不出调整（第四节第 11 步）。
- 没有 `广告闭环/输出/经营.json`：只能按目标 ACOS 和盈亏线解释清单里的动作，谈不了单品预算和任务。

## 三、脚本算什么，你做什么

| 脚本算 | 你做 |
|---|---|
| 每个关键词、定位、自动组近窗口的点击、订单、花费、ACOS | 只读 |
| 分档结果：暂停、降、提、不动；新竞价（按口径的调幅，取整时往安全一侧） | 解释为什么落在这一档；检查任务是否支持这个动作 |
| 结构压价：词组、广泛压到精确之下 | 解释层次；指出人驳回过的 |
| 活动层：改竞价策略、下调默认竞价、预算上调或下调 | 解释；对上单品预算 |
| 验证器：单次调幅不越线、一个对象一轮只动一次 | 读结果 |
| — | 按公式给出 CPC 天花板（式子和代入的数都写出来） |
| — | 判断是出价问题还是别的问题（流量小、Listing、库存） |
| — | 给每个调整答三问，定观察节奏 |

新值以脚本为准。你算的天花板是参照，用来说明新值离天花板还有多远，不用来替换脚本的数。

## 四、判断步骤

1. **先问任务。** 读这个对象所在活动的任务（`任务` 或人确认的）。推自然位的词 ACOS 高于盈亏线，不直接当成该降；纯利型、收割的词高于目标就该处理。任务是 `未判定` 的活动，只解释清单里的动作，不追加建议，并请人先去「广告活动」页确认任务。
2. **过样本闸。** 点击、订单没到口径门槛的对象，结论是「样本不足，不动」。归因未满的天不算。上一圈刚动过、还在 `复盘.大改冷静期天数` 之内的对象，也不动。
3. **算 CPC 天花板。** 天花板 ＝ 目标 ACOS × 客单价 × 这个对象自己的转化率。点击没过 `门槛.CPC天花板自身转化率点击` 时，转化率改用有转化的词的平均值，结果标「基准值」。把现在的实际 CPC 和天花板摆在一起：高出多少，或还有多少空间。
4. **分档。** 和脚本的规则一致，细则见 `references/规则.md` 第一节：
   - 零单且点击过门槛 → 暂停（关键词、定位、自动组各有各的门槛）。
   - ACOS 高于盈亏线且点击够 → 降，单次降 `调幅.竞价单次下调`，不低于 `调幅.最低竞价`；验证器的硬线是 `调幅.竞价单次调幅上限`。
   - ACOS 低于目标的 `判定.提竞价ACOS相对目标` 且订单够、所在活动没有库存风险 → 提，单次 `调幅.竞价单次上调`。
   - 其余 → 不动。「不动」要写出来，它也是结论。
5. **先分清是不是出价的问题。** 三种情况不该用调价解决，细则见 `references/规则.md` 第二节：
   - 曝光很低（低于 `判定.日曝光过低`）但出价已经到了天花板：这个词本身流量小，标出来，不再加价。
   - 点击率很低（低于 `判定.点击率过低`）而 ACOS 高：是 Listing 吸引不了点击，转给 `ads-diagnose`。
   - 所在活动挂着将断货的规格：先处理库存，提价和加预算一律不提。
6. **要加价时：走走停停，先横后纵。** 曝光和点击不够才加，一次一小步；已经有点击、有订单就停手观察，不连着加。先让更多能成单的词拿到曝光，再去拉单个词的出价。
7. **要降价时：按周小步。** 每次降一档，隔一个观察窗口看三样：订单丢没丢、CPC 降没降、利润变没变。订单没明显减少就继续下一步。降出价不等于花费同比例下降，流量和转化要一起看。成熟链接的微调幅度见 `调幅.稳定期微调幅度`。
8. **看结构。** 精确应当高于词组，词组高于广泛。倒挂的由结构压价处理（`竞价调整表.csv`）。一个对象一轮只动一次：结构压价动过的，表现规则不再叠加。
9. **预算：先对总边界，再看单个活动。**
   - 总边界：`算账.单品日预算` 对 `现日预算合计` 和 `上周日均广告费`，三种情况的读法见 `ads-profit-target`。
   - 单个活动加预算要三样都在：日均花费到了预算的 `判定.预算吃紧比例`；ACOS 在目标内；没有库存风险。任务是目的型且达标的优先。
   - **禁止**：预算花完了、但 ACOS 高于盈亏线的活动，不加预算。花完不是理由。
   - 降预算：组里有规格一周内断货、而补货到仓周数不超过 `判定.到仓快只降预算的周数上限`，脚本会出「下调预算」，到仓后恢复。预算单次调整的硬线是 `调幅.预算单次调整上限`。
   - 所有活动加起来超过单品日预算时，提醒这一点，加谁减谁要人定。
10. **竞价策略和默认竞价。** 整个活动 ACOS 高于盈亏线且点击过 `门槛.活动级判断点击`：策略是「提高和降低」的建议改成「只降低」，默认竞价同步下调，免得新加的投放从高价起步。新活动和测试期的活动用固定竞价，数据才读得清。
11. **广告位。** 先看有没有按广告位拆开的报表：
    - 没有：只说「设了加价的活动有哪些、各加了多少，但看不出值不值」，对应清单里的「广告位待补数据」，不出任何调整。
    - 有：按 `references/规则.md` 第四节读三个位置的曝光比、点击成本和转化，判断现在的出价落在哪一档、加价是否换来了合算的订单。
    - 自动投放多个组混在一起、一个活动里词根差别很大、预算每天很早花完的活动，广告位的数会失真，先说这一点。
12. **排优先级。** 按涉及花费从大到小排；先处理暂停和降价，再处理提价和加预算。列出本轮最要紧的三到五条，其余按类型汇总。

## 五、常见情形

**情形 1：一个词 ACOS 高于盈亏线，所在活动的任务是推自然位**

- 读到：清单里有它的「关键词降竞价」；`任务` 里这个活动是推自然位。
- 判断：规则按表现出了动作，但任务允许它暂时成本高。该不该降，取决于自然位有没有在改善、观察期过没过。
- 怎么答：解释脚本为什么出这条；说明它和任务有冲突；把「降还是继续」交给人，并指向 `ads-campaign-task` 看任务完成情况。
- 不要：只说「超盈亏线，建议通过」。

**情形 2：点击很少的对象**

- 读到：点击没过 `门槛.关键词降竞价点击`，也没过零单暂停的门槛。
- 判断：样本不足。
- 怎么答：归到「不动」，写明现在几次点击、门槛是几次。
- 不要：用它那几次点击算出的 ACOS 说事。

**情形 3：预算每天下午就花完，活动 ACOS 高于盈亏线**

- 读到：近 7 天日均花费接近日预算；活动 ACOS 高于 `四周.盈亏线`。
- 判断：命中禁止条件。加预算等于多亏。
- 怎么答：明确不加；先看这个活动里哪些对象超了天花板，降下来之后同样的预算能撑更久。
- 不要：因为「花完了」就同意加。

**情形 4：曝光很低，出价已经到了天花板**

- 读到：日曝光低于 `判定.日曝光过低`；实际 CPC 接近算出来的天花板。
- 判断：这个词本身流量小，不是出价不够。
- 怎么答：标「词本身流量小」，不再加；要量去找别的词，交给 `ads-search-term`。
- 不要：建议「再加一点试试」。

**情形 5：没给关键词竞价表**

- 读到：清单里没有任何关键词层面的调价动作；验证器里相关项跳过。
- 判断：不知道现价，出不了动作。
- 怎么答：仍然可以给天花板，例如目标 ACOS 25% × 客单价 30 × 转化率 12% ≈ 0.90；说明「现价请到后台核对，高于它的先降」；指出要补的表。
- 不要：编一个现价。

**情形 6：问「搜索顶部加价值不值」，没有广告位报表**

- 读到：`广告活动` 页显示设了加价；清单里有「广告位待补数据」。
- 判断：没有按位置拆开的花费和订单，判断不了。
- 怎么答：列出哪些活动各加了多少；说明看不出值不值；指出要补哪份报表。
- 不要：凭「顶部转化一般更好」之类的印象给建议。

**情形 7：降价之后用户担心掉单**

- 读到：上一圈已执行的降竞价动作；这一圈该对象的订单和 CPC。
- 判断：看订单有没有明显减少。冷静期内不下结论。
- 怎么答：订单稳、CPC 降 → 可以再降一档；订单明显少 → 停在上一档。位置后移本身不是问题。
- 不要：一看到位置变了就建议加回去。

## 六、输出

- 按 `../ads-shared/输出格式.md`，加 `templates/输出.md` 的出价表、预算表、广告位表。
- 每条调整都带「可执行 / 缺什么才能执行」和三问。
- 只在对话里回答，不写 `广告闭环/输出/AI补位.json`。
- 动作引用编号，指到「行动 · 待你决定」；你认为该动而清单没出的，列为「清单外建议」并说明规则为什么没出。

## 七、不许做的

- 不给超过口径调幅的建议，不建议一步到位。
- 不在样本不够时出暂停、降价、提价。
- 不给预算花完且 ACOS 高于盈亏线的活动加预算。
- 不给有库存风险的活动提价、加预算。
- 不在没有广告位报表时建议改广告位加价。
- 不把「现值」写成你猜的数。没有竞价表就写缺。
- 不替换脚本的新值。
- 不说「已调整」。
- 不在任务未判定时追加调整建议。

## 八、自查三句

1. 我提到的每个调整，对象所在活动的任务我看过吗？这个动作和任务不冲突吗？
2. 每个新值都在口径的调幅之内吗？天花板的式子和代入的数我写出来了吗？
3. 加预算的建议，三个条件（吃紧、ACOS 在目标内、没有库存风险）是不是都核过？
