# ads-weekly-review · 规则

阈值都引用 `口径.json` 的键，含义见 `../ads-shared/公式与口径.md` 第八、九节；复盘窗口的定义见同一文件第七节（路径都从本 skill 目录算起）。

## 一、数据体检五项

| 项 | 怎么看 | 不过时 |
|---|---|---|
| 必需输入齐不齐 | 运行记录里缺输入的提示；退出码 2 | 这一圈不出结果。说清缺哪份、去哪取。上一份有效结果还在，但要标日期 |
| 覆盖天数 | 搜索词报告至少要盖住两个窗口 | 前一个窗口不完整时，环比不可信，只看近窗口的水平 |
| 口径核对 | `口径核对` 里两份报告的花费差（允许偏差见 `判定.报告花费口径允许偏差`）；活动报告缺失时由搜索词报告聚合，会有标记 | 差得多：先查两份报告的日期范围；在核清之前活动层的结论不出 |
| 验证器 | `广告闭环/输出/验证器.json` 逐项 | 任何一项不过，整轮动作作废。把不过的那项原文给人 |
| 归因未满 | `参数.json` 的 `归因未满` | 不算不过，但凡是用到这几天的数都要标 |

验证器守的是底线：不否自家品牌词、不否出过单的词、不重复否、单次调幅不越线、收割和来源组否定成对、所有动作停在待确认、只出人选中的取舍项。它过了只说明没越线，不说明动作是对的。

## 二、三种判定的条件

| 判定 | 必须同时满足 |
|---|---|
| 有效 | 约定的数朝预期方向变了；两个窗口的订单都过 `门槛.复盘下结论订单`；观察期已满；同期没有别的大变动能解释这个变化 |
| 无效 | 样本够、观察期已满；约定的数没变或反向变了 |
| 看不出 | 以上任一条件不满足 |

「同期别的大变动」包括：调价、优惠券或促销、断货或到货、别的动作同时作用在同一个对象上、季节拐点、对手明显的价格动作。有其中之一，结论最多写到「方向一致，但不能单独归因」。

几类动作各自看什么数：

| 动作类型 | 看什么 | 有效的样子 |
|---|---|---|
| 降竞价类 | 对象的 CPC、订单 | CPC 降了，订单没有明显减少 |
| 提竞价、预算上调 | 对象或活动的订单、ACOS | 订单多了，ACOS 仍在目标内 |
| 暂停类、否定类 | 被停掉的花费去哪了；所在活动的 ACOS | 这部分花费没了，活动订单没有明显减少 |
| 换道否定、搜索词收割 | 头部词在非主干组的花费；精确组占头部词花费的比例 | 前者趋近于零，后者上升 |
| 暂停广告产品、补挂广告产品 | 整体可售周数（恢复线见 `复盘.可售周数恢复线`）；补挂规格的转化率对比原规格 | 断货规格不再花钱；补挂的接得住 |
| 竞品词降价单独跑 | 这个词的 ACOS | 回到盈亏线内 |
| Listing 建议稿 | 退款率、退货首因占比 | 滞后，通常一个周期看不出 |

短周期的价值是及早发现方向，不是用很少的订单宣布因果。两个时点：第 `复盘.初查天数` 天初查（只看花费和点击有没有按预期变，不下结论），第 `复盘.决定天数` 天决定继续、调整还是停。

## 三、每周看的四个面

### 结构

- 各规格的销量占比、可售周数：主推是不是还撑着大部分销量，有没有规格快断货。
- 广告产品是不是还挂在将断货的规格上。
- 活动数、名义日预算合计有没有变。

### 指标

- 库存动销：整体可售周数对补货到仓周数。
- 目标与实际：`算账.判定` 和上一圈比有没有变；TACOS 余量是变大还是变小。
- 盈利模型：定价毛利率有没有变（退款、促销会让它变）。

### 归因

- 找出环比变化最大的一个指标，交给 `ads-diagnose` 的步骤走到一个核心限制。
- 周报里只写结论和一句依据，不展开全表。

### 时间线

- `逐周` 至少看四周：这周是延续，还是拐点。
- 末周广告费增速和件数增速谁快（`末周环比`）：广告费涨得比件数快，多花的钱没有换来等比例的单。
- 单看一周的涨跌容易误读；连续两周同方向才算趋势。

## 四、审的顺序

| 先后 | 审什么 | 典型发现 |
|---|---|---|
| 一 | 动作到位了吗 | 通过了没去后台做；做了一半；做了但标错了日期；被别的改动覆盖了 |
| 二 | 盈利模型对吗 | 目标定得和阶段不配；路径选的前提不成立；任务定错了 |
| 三 | 产品定位对吗 | 价格、评价、图片接不住流量；需求本身在变 |

前一层有问题就停在那一层。动作没到位时去怀疑路径，是在错误的数据上换方向。

## 五、周报的写法

- 三个小节，标题固定：「这周结论」「要你拍板」「下周看什么」；不超过 400 个字。第一句是这周的结论。
- 上周动作的结果和经营结论放第一节；待审批和要人定的事放第二节；复盘日、要盯的数、还缺的数据放第三节。
- 数字原样照抄脚本产物，不心算新的百分比和金额：出现材料里没有的数，整份草稿会被校验丢弃。
- 上周动作的结果只列判定和一个关键数；有效的写下一步怎么放大，无效的写怎么撤，看不出的写等到哪天。
- 要你决定的：待审批条数按取舍项汇总，不逐条列；另外列要人定的事（目标、路径、任务确认）。
- 语气：给老板看的，不用术语堆砌；不报喜不报忧，数据到哪话到哪。
- 群消息版本更短：三到五行，结论、待办条数、复盘日。仍然只是草稿。
- 和上一份周报口径保持一致：同一个指标用同一个窗口、同一个名字。

## 六、停下来等人的三种情况

| 情况 | 为什么停 | 怎么说 |
|---|---|---|
| 连着两次缺资料 | 再跑也是空转 | 「连续两圈缺某某，之后不再自动跑，补齐后请手动触发」 |
| 单日花费比平时翻了几倍 | 可能是后台出了意外改动或异常点击 | 「某日花费异常，请先到后台核对，核完再决定这一圈的动作作不作数」 |
| 行动卡已结案 | 这一轮的事做完了 | 「这张行动卡已结案，下一轮从新的目标开始」 |

## 七、常见的「没跑成」

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 提示某活动名不在报表里 | `参数.json` 里指定的精确、词组、广泛活动名和报表对不上 | 照提示里列出的活动名改，一个字都不能差 |
| 报告只覆盖十几天 | 导报告时日期范围太短 | 重新导足够天数的报告 |
| 两份报告花费差得多 | 日期范围没对齐 | 对齐后重导 |
| 验证器有一项不过 | 多半是词表或状态读回出了问题 | 把那一项原文给人；不要绕过 |
| 模型补位是 `skipped` | 没接模型或通道不通 | 脚本产物照常可用；通道状态看工作台的健康检查 |
| 模型补位是 `partial` | 模型给了不在枚举里的值，被丢弃 | 看是哪个键缺了；下一圈重跑补位 |
| 重复触发没反应 | 输入没变 | 正常；要强制重跑先改输入或在页面重置 |
