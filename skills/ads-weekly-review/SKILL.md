# ads-weekly-review · 每周一圈与复盘

工作台不是跑一次出一张表就完了。它每周转一圈：读回上周的状态，算这周的数，出动作，等人审批，到日子回头看效果。你在这一圈里的角色是把前后两周接起来，说清上周做的事有没有用，并把这一周要人知道的事写成一页周报草稿。

共用规矩在 `../ads-shared/`：`分工与红线.md`（先读）、`公式与口径.md`、`输出格式.md`、`术语.md`。本 skill 的细则在 `references/规则.md`，输出模板在 `templates/输出.md`。

## 一、什么时候用，什么时候不用

用：

- 「跑一下本周」「这周的周检出来了吗」
- 「出一份周报」
- 「上周降的那几个词，有效果吗」
- 「到复盘日了，帮我过一遍」
- 「这一圈为什么显示遇到问题」
- 「这周和上周比，哪里变了」
- 「Agent 每周一是怎么自己跑的，我要做什么」

不用：

- 只问某一个指标为什么变：`ads-diagnose`（复盘时你会调用它的拆解，但单问原因直接去那里）。
- 只问接下来走哪条路：`ads-path-decision`。
- 只问某条动作的数怎么来的：`ads-bid-budget` 或 `ads-search-term`。
- 新品期每周的节奏对不对：`ads-launch`（周报里的新品部分引用它的结论）。

| `广告闭环/输出/读回状态.json` | `读回时间`、`被驳回的动作`（含驳回理由）、`已处理的动作` | 人上一圈点了什么 |

| `广告闭环/行动卡/` 下最近一张行动卡 | 第 9 栏「复核证据与观察期」 | 上一圈约定到日子要看哪几个数 |

| `广告闭环/输出/数字.json` | `逐周`、`四周`、`末周环比`、`SP-前14天`、`SP-近14天`、`活动表`、`分组账-前14天`、`分组账-近14天`、`库存`、`异常`、`口径核对` | 两个窗口的对比 |
| `广告闭环/输出/经营.json` | `算账`、`拆解`、`任务`、`路径`、`决策表` | 经营结论 |
| `广告闭环/输出/验证器.json` | 每项是否通过 | 这一圈的底线 |
| `广告闭环/输出/动作清单.json` | 这一圈的新动作，按取舍项和类型 | 周报里的「要你决定的」 |
| `广告闭环/输出/AI补位.json` | `状态`、`原因`、`周报草稿` | 模型补位跑没跑 |
| `运行记录/周报-*.md` | 上一份周报 | 口径和措辞保持连续 |
| `口径.json` | `复盘.观察天数`、`复盘.初查天数`、`复盘.决定天数`、`复盘.可售周数恢复线`、`判定.报告花费口径允许偏差`、`调幅.竞价单次调幅上限`、`调幅.预算单次调整上限`；暂定键 `复盘.大改冷静期天数`、`门槛.复盘下结论订单`（读不到只说方向） | 复盘时引用 |

页面对应：「Agent 运行」页（每一圈的六格、运行记录、操作记录）和「首页」（今天要处理什么、这周的结论）。持续运行的历史回放在同一页，只读。

拿不到时：

- 没有 `运行记录/runs.jsonl`：还没用每周流程跑过。可以用现有产物做一次复盘式的对比，说明「没有运行记录，以下只基于最新一份产物」。
- 没有上一圈的状态（`已处理的动作` 为空）：没有可复盘的动作。只做两个窗口的对比，不谈动作效果。
- 人通过了动作但没标已执行：不知道后台到底改没改。复盘前先问，或写「执行情况未确认，效果无法归到这条动作上」。
- 缺输入：见第四节第 2 步。报表怎么补看 `数据格式.md`。

## 三、脚本算什么，你做什么

| 脚本做 | 你做 |
|---|---|
| `_脚本/weekly.py`：读回状态 → 数据体检 → 跑一圈（算数、出动作、验证、写状态）→ 经营核算 → 模型补位 → 自检 → 起草周报 → 留痕 | 被问到时解释每一步的结果；不代替它跑里面任何一步的计算 |
| 读回：把页面上人通过、驳回的结果写进读回状态；驳回过的下一圈不再原样提，确认过的沿用 | 把驳回理由读出来，当作这一圈的约束 |
| 验证器九项，任何一项不过整轮作废 | 把不过的那一项翻成人话，说清要补什么 |
| 两个窗口的全部指标 | 复盘：把变化归到动作上，或者说明归不上 |
| 追加一行运行记录；有失败退出码 1，缺输入退出码 2 | 读这一行，判断这一圈可不可信 |
| — | 判定每条已执行动作：有效、无效、看不出 |
| — | 起草周报 |

## 四、判断步骤

1. **读回上一圈。** 先弄清四件事：上一圈出了多少动作；人通过了哪些、驳回了哪些、理由是什么；通过的里面哪些已标执行；上一张行动卡约定这次要看哪几个数。驳回理由是人给的规则，这一圈的任何建议都不能和它冲突。
2. **数据体检。** 这一圈的数能不能用，看五样，细则见 `references/规则.md` 第一节：
   - 缺不缺必需的输入：`参数.json` 的目标 ACOS、补货到仓周数、产品阶段三样必填，加上必需的报表（缺 → 这一圈直接停，不拿旧数据硬跑，上一份有效结果不动）。
   - 报表覆盖的天数够不够两个窗口。
   - 口径核对：搜索词报告和活动报告的花费差得多不多。
   - 验证器有没有全过。
   - 归因未满的是哪几天。
   有一样不过：先说这一样，后面的结论全部降级或不出。
3. **跑这一圈，或确认已经跑过。** 用户让你跑：先用 `python3 _脚本/weekly.py --dry-run` 把会做什么说一遍（不写状态库、不跑流水线、不调模型、不写周报文件，只记日志和运行记录），对方确认后再真跑 `python3 _脚本/weekly.py`。数据目录不是仓根时加 `--root`，不想调模型加 `--no-llm`。跑完读运行记录最后一行：哪步失败了、动作数、待审批数、模型调用了几次。你不直接运行流水线里的单个脚本去改产物。
4. **定复盘窗口。** 等长窗口，规则在 `../ads-shared/公式与口径.md` 第七节：改动前后各取同样天数；都去掉变更当天；改动后的去掉归因未满的那几天。动作执行日不清楚时，用人标「已执行」的日期；连这个也没有，写看不出。
5. **逐条判定已执行的动作。** 每条看行动卡或三问里约定的那个数：
   - 有效：约定的数朝预期方向变了，样本够（`门槛.复盘下结论订单`），同期没有别的大变动能解释它。
   - 无效：样本够，约定的数没变或反向变了。
   - 看不出：样本不够、观察期没满（`复盘.初查天数`、`复盘.决定天数`）、同期有别的改动或促销、执行情况没确认。
   「看不出」写清还要等多久、等什么。观察期没满只报进度，不下结论。
6. **按顺序审，不跳步。** 先审动作有没有做到位（通过了没执行、执行了一半，都算没到位）；动作到位了没效果，再审盈利模型（目标、路径是不是选错了）；模型也没问题，最后才审产品本身（价格、评价、定位）。大多数「没效果」停在第一步。
7. **看这一周的四个面。** 细则见 `references/规则.md` 第三节：
   - 结构：各规格的销量和库存分布，主推稳不稳。
   - 指标：库存够卖几周、目标和实际差多少、算账判定有没有变。
   - 归因：变化最大的那个指标，按 `ads-diagnose` 的拆解走一遍，交出一个核心限制。
   - 时间线：逐周环比，这周是延续趋势还是拐点。
8. **对上路径。** 人上一圈选的路径还成立吗？复盘结论对应决策表的「后续选择」：有效 → 按约定放大；无效 → 按约定撤回，并回到 `ads-path-decision` 换路；看不出 → 延长。路径中途被换了目标的，指出来。
9. **起草周报。** 三个小节，标题固定为「这周结论」「要你拍板」「下周看什么」，不超过 400 个字，模板在 `templates/输出.md`。这周结论里写经营结论（算账、核心限制、路径）和上周动作的结果；要你拍板里写待审批条数（按取舍项汇总）和要人定的事；下周看什么里写复盘日、要盯的数、还缺的数据。只用脚本产物里的数，原样照抄。
10. **说清谁来发。** 周报是草稿。发到群要人在页面上点；发过的会记在 `运行记录/sent.log`。你不发，也不说「已发」。
11. **判断要不要停下来等人。** 三种情况这一圈之后不该自动继续，要明确请人接手：连着两次缺资料；单日花费比平时翻了几倍；行动卡已经结案。

## 五、常见情形

**情形 1：动作通过了，但没人标「已执行」**

- 读到：读回状态里这条动作是通过；页面上不是已执行。
- 判断：不知道后台到底改没改。
- 怎么答：先问；没法确认就写「执行情况未确认，效果无法归到这条动作上」，判定 `看不出`。
- 不要：默认它执行了，然后分析效果。

**情形 2：降竞价之后 CPC 降了、订单也略降，同一周促销刚结束**

- 读到：这条动作约定看 CPC 和订单；同期有促销结束。
- 判断：订单下降有另一个解释。
- 怎么答：写「方向一致，但不能单独归因」，判定 `看不出`；建议再看一个不含促销的窗口。
- 不要：判「无效，导致掉单」，也不要判「有效」。

**情形 3：观察期还没满**

- 读到：动作执行到现在的天数还没到 `复盘.决定天数`。
- 判断：只能报进度。
- 怎么答：写现在的数和方向，标「进度，未到决定日」；写明哪天下结论。
- 不要：提前宣布有效或无效。

**情形 4：验证器有一项没过**

- 读到：`广告闭环/输出/验证器.json` 里某项 `通过` 为否。
- 判断：整轮动作作废。
- 怎么答：把那一项原文给人，说明多半是哪里出了问题、要补什么；不谈这一圈的动作。
- 不要：挑「其他没问题的动作」继续讲。

**情形 5：模型补位这一圈是 skipped**

- 读到：`广告闭环/输出/AI补位.json` 的 `状态` 是 `skipped`，带着原因。
- 判断：脚本产物照常可用，只是没有模型写的那几段文字。
- 怎么答：告诉用户补位没跑、原因是什么；这次在对话里把核心限制、路径建议现场说一遍。
- 不要：把上一圈的补位内容当成这一圈的。

**情形 6：连着两圈都缺同一份报表**

- 读到：运行记录最近两行都是缺输入。
- 判断：命中停止条件。
- 怎么答：明确说之后不该再自动跑；写清缺哪份、去哪取、补齐后怎么手动触发。
- 不要：每周照常出一份空周报。

## 六、Agent 每周怎么跑

- 触发有三种：人在页面点「跑一圈」；定时任务每周固定时间直接运行 `_脚本/weekly.py`（不经过模型；节奏写在 `ads.config.json` 的 `weekly.schedule`）；人来问你。
- 定时跑的那一次，你被 `_脚本/llm.py` 调用，只做模型补位：核心限制一句话、路径建议、任务标签、搜索词补位、决策表草稿、周报草稿。输出经校验后写进 `广告闭环/输出/AI补位.json`；枚举不合法的被丢弃并记 `partial`；没接模型就是 `skipped`（模型通道在 `ads.config.json` 的 `llm` 段）。
- 每一步失败只记进 `problems`，不拦后面的步骤；唯一的例外是缺输入，直接停，退出码 2。所以读运行记录时要逐步看，不能只看最后有没有周报。完整日志在 `运行记录/` 下同一时间的日志文件里。
- 输入没变时重复触发不会重跑。改了目标、到仓周数、取舍项或数据，任务会回到待处理。
- 跑完之后要人做的只有三件：到「行动 · 待你决定」逐条审批；到「广告活动」页确认任务；看一眼周报草稿，要发就点发。
- 模型补位的质量由考卷检验：`评测/` 下是考卷和评分口径，`_脚本/eval.py` 负责跑。改了技能包或换了模型之后跑一遍。

## 七、输出

- 按 `../ads-shared/输出格式.md`，加 `templates/输出.md` 的复盘表和周报模板。
- 平时在对话里回答。每周一圈时，周报草稿由 `_脚本/llm.py` 写进 `广告闭环/输出/AI补位.json` 的 `周报草稿`（Markdown），`_脚本/weekly.py` 另存一份到 `运行记录/周报-*.md`。
- 复盘不新增动作。要调整的，指回对应 skill。

## 八、不许做的

- 不在体检没过时照常出结论。
- 不拿旧产物冒充这一周的结果。
- 不把同期发生的变化都算成动作的功劳，也不都算成动作的过错。
- 不在观察期没满、样本不够时判有效或无效。
- 不替人标「已执行」，不替人发群，不说「已发出」。
- 不绕过驳回理由重提旧动作。
- 不直接改 `广告闭环/输出/` 下的任何文件，不写 `工作台.db`。
- 不在周报里写脚本产物里没有的数。

## 九、自查三句

1. 我先读了上一圈的驳回理由和已处理动作吗？这一圈的话有没有和它们冲突？
2. 每条被我判为「有效」或「无效」的动作，窗口等长吗、去掉了变更当天和归因未满的天吗、样本过线了吗？
3. 周报里的每个数都指得出来源吗？有没有哪句话读起来像是「已经发了」「已经改了」？
