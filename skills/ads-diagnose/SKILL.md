# ads-diagnose · 拆指标找限制

你的任务是把「数不好看」变成「卡在哪一个变量上」。一次诊断只交出一个核心限制，不是一张问题清单。找到限制之后该怎么办，交给后面的 skill。

共用规矩在 `../ads-shared/`：`分工与红线.md`（先读）、`公式与口径.md`、`输出格式.md`、`术语.md`。本 skill 的细则在 `references/规则.md`，输出模板在 `templates/输出.md`。

## 一、什么时候用，什么时候不用

用：

- 「TACOS 这周怎么涨了」
- 「ACOS 高，是出价的问题还是转化的问题」
- 「利润率比上个月掉了，掉在哪」
- 「单量没达到预期，查一下」
- 「这周突然卖多了，是市场涨了还是我们做对了什么」
- 「广告都在目标内，为什么还是不赚钱」

不用：

- 账还没算（没有目标 TACOS）：先 `ads-profit-target`。没有目标，「高」和「低」无从说起。
- 已经知道限制是什么、要定怎么办：`ads-path-decision`。
- 要看某一个活动该不该留：`ads-campaign-task`。
- 要看具体哪些词该否、该收：`ads-search-term`。
- 要复盘上周的动作有没有效：`ads-weekly-review`（它会回头调用这里的拆解）。
- 新品期的节奏问题（推得快了慢了）：`ads-launch`。

边界一句话：这里回答「卡在哪」，不回答「怎么办」。

| `口径.json` | `经营.CPC环比涨幅警戒`、`经营.CVR环比下滑警戒`、`经营.无效广告花费占比警戒`、`经营.广告销售额占比警戒`、`经营.相对目标偏低线`、`判定.退款率警戒`、`判定.广告费增速高于件数增速的容差`；暂定键 `判定.点击率过低`、`复盘.大改冷静期天数`（读不到只说方向） | 解释脚本的判定用了哪条线 |

页面对应：「原因」页（问题 → 分析 → 对策 → 动作的连线由 `_脚本/tree.py` 生成）和「首页」的本周结论。

拿不到时：

- 没有 `广告闭环/输出/经营.json`：让用户先跑一圈或运行 `python3 _脚本/weekly.py --dry-run`。只有 `广告闭环/输出/数字.json` 时，可以用 `逐周` 和两个窗口做指标拆解，但不能给核心限制（缺目标），输出里写明。
- 没有广告位报表、分时段数据：分层走到那一层时写「缺」，停在上一层。要补什么见 `数据格式.md`。
- 没有自然排名、市场搜索量：归因路径里「市场涨跌」「自然还是广告」这两步只能写「看不出」，并说明要查得花钱取数。
- `拆解.核心限制` 是 `null`：脚本没判出来，按第四节走完后给出你的候选，标「AI 判断，脚本未判定」。

## 三、脚本算什么，你做什么

| 脚本算 | 你做 |
|---|---|
| 六个节点的值、环比、是否偏高偏低 | 把节点连成一句话：哪个动了、带动了谁 |
| 核心限制的变量、命中的规则、依据 | 用一句运营听得懂的话解释它；检查依据站不站得住 |
| 归因路径的入口和逐层步骤 | 检查每一步有没有数；没数的那步标「看不出」 |
| 异常清单和级别 | 区分哪些是限制本身、哪些只是它的后果 |
| 断货后等效 ACOS | 解释这个数的前提（买不到想要规格的人会直接走） |
| — | 分清是转化问题还是出价问题 |
| — | 写出「什么情况下这个判断不成立」 |

脚本给了核心限制，你就解释它，不换成别的。你认为它判错了：把脚本的结论写在「规则判断」，把你的看法和证据写在「AI 判断」，最后让人定。

## 四、判断步骤

1. **先过库存这一关。** 读 `库存` 和 `异常`。主力规格可售周数撑不到补货到仓：核心限制就是 `库存`，后面的拆解照做，但结论里库存排第一。原因很简单：货不够时，把别的都调好也卖不出去，广告还在给买不到的规格买点击。
2. **对目标。** 读 `算账.判定` 和 `TACOS余量`。在目标内且余量充足、用户也没有具体的不满：核心限制可以是 `无明显限制`，直接说，不硬找问题。
3. **拆第一层：TACOS ＝ ACOS × 广告销售额占比。** 看 `拆解.节点` 里这三个节点的 `变化` 和 `判定`：
   - ACOS 动了、占比没怎么动 → 广告效率的问题，进第 4 步。
   - 占比动了、ACOS 没怎么动 → 订单结构的问题，进第 5 步。
   - 两个都动了 → 两步都走，但最后只报贡献大的那个。
   - 都没动，TACOS 也没动，只是一直偏高 → 这是水平问题不是变化问题，看 ACOS 和占比各自相对目标的位置。
4. **拆第二层：ACOS ＝ CPC ÷（转化率 × 客单价）。** 三选一：
   - CPC 涨、转化率平：出价或竞争的问题。再看是不是某几个活动、某类词带起来的（`活动表`、`分组账-近14天`）。
   - 转化率跌、CPC 平：承接的问题。先排除归因未满；再看是买错了词（泛词、跑偏词占比上升），还是词没变、页面接不住（价格、评价、主图、断货规格、退款率上升）。
   - 客单价变了：看是调价、促销，还是卖出去的规格结构变了。
   - 点击率很低（低于 `判定.点击率过低`）同时 ACOS 高：这是 Listing 的问题，不是出价的问题，别让人去调竞价。
5. **占比高而效率正常时。** 两种可能，都要查：
   - 自然订单没被带出来：广告单在涨，总单没等比例涨。查不了自然排名时写「看不出，缺自然排名」。
   - 有广告还在做没有结果的事：推了很久的词自然位没动、泛词一直亏。这是 `无效广告`，交给 `ads-campaign-task` 逐个活动看任务。
6. **走归因路径。** 读 `拆解.归因路径.入口`，三个入口各自的下钻顺序在 `references/规则.md` 第二节。逐步复述脚本的 `步骤`，每一步一句、带数；哪一步没有数据支撑，写「这一步看不出，缺某某」，不跳过，也不猜。
7. **按分层顺序往下定位。** 目标 → 父体整体 → 活动 → 广告组或投放 → 搜索词 → 广告位 → 时段。每下一层先问：上一层的差距，有多大一部分能被这一层的某几个对象解释？能解释大半就停，不必走到底。缺数据的层写缺。
8. **只报一个核心限制。** 从七类里选：`库存`、`CPC`、`CVR`、`广告销售额占比`、`无效广告`、`利润空间`、`无明显限制`。脚本按固定顺序判、命中第一条即停，顺序见 `references/规则.md` 第三节。其余发现写进「同时看到的」，最多三条，标明它们是后果还是独立问题。
9. **写不成立的条件。** 每个推断后面跟一句「如果某某，这个判断不成立」。例如「如果买不到想要规格的人会自己换一款，断货的影响就没这么大」。
10. **交棒。** 按核心限制指出下一个 skill（表在 `references/规则.md` 第四节），一句话说明让它回答什么。

## 五、常见情形

**情形 1：TACOS 涨了，ACOS 基本没动，广告销售额占比涨了**

- 读到：三个节点里只有占比的 `判定` 是偏高。
- 判断：广告效率没变差，是订单更依赖广告了。走第 5 步。
- 怎么答：核心限制在 `广告销售额占比` 和 `无效广告` 里选；有成规模的未达标广告就是后者。说明自然单有没有起来「看不出，缺自然排名」。
- 不要：建议降竞价。效率没问题时降价解决不了占比。

**情形 2：ACOS 涨了，CPC 涨、转化率平**

- 读到：CPC 节点上升，CVR 节点正常。
- 判断：出价或竞争的问题。再看是每个活动都涨，还是钱更多地流向了贵的活动。
- 怎么答：核心限制 `CPC`；指出集中在哪几个活动；交给 `ads-bid-budget`。
- 不要：把结构变化（花费重心移到贵的活动）说成「竞争加剧」。

**情形 3：转化率掉了，同一时期主力规格快断货**

- 读到：CVR 节点下降；`库存` 里主力规格可售周数不到补货到仓周数。
- 判断：库存压过一切。转化下降多半是它的后果。
- 怎么答：核心限制 `库存`；转化率下降写进「同时看到的」，标为后果；写明「如果买家会自己换规格，影响没这么大」。
- 不要：报 `CVR`，然后让人去改 Listing。

**情形 4：近窗口的转化率低，但窗口末尾几天归因未满**

- 读到：`参数.json` 的 `归因未满`；近窗口末尾几天订单明显少。
- 判断：这几天的订单还会补记。直接比会高估下降幅度。
- 怎么答：先说这一点；能去掉这几天再比就比，不能就写「看不出，等归因补齐」。
- 不要：据此下「转化变差」的结论。

**情形 5：各项都在目标内，用户仍然觉得「不对劲」**

- 读到：`算账.判定` 在目标内；节点都正常；库存够。
- 判断：没有限制也是结论。
- 怎么答：核心限制 `无明显限制`；说明余量有多少；如果他想要的是更多利润额，交给 `ads-path-decision`。
- 不要：为了显得有用硬找一个问题。

**情形 6：脚本判的是 CPC，你认为其实是转化**

- 读到：`拆解.核心限制.变量` 是 CPC；你看到泛词花费占比在升、转化率也在缓慢下降。
- 判断：可以有不同看法，但不能替换脚本的结论。
- 怎么答：「规则判断」栏照写脚本的 CPC 和它命中的规则；「AI 判断」栏写你的看法、证据、怎么验证；请人定。
- 不要：只写你自己的结论，把脚本的抹掉。

**情形 7：只有时间上的重合**

- 读到：末周增长放缓，同一周有规格断货。
- 判断：两件事同时发生，不等于一件导致另一件。
- 怎么答：写「时间重合，证据弱」；说明到仓之后如果增长恢复，就能验证。
- 不要：写成「增长放缓是断货造成的」。

## 六、输出

- 按 `../ads-shared/输出格式.md` 的四栏表，加 `templates/输出.md` 的拆解表和归因路径。
- 平时只在对话里回答。
- 每周一圈时，你给出的「核心限制一句话」由 `_脚本/llm.py` 写进 `广告闭环/输出/AI补位.json` 的 `核心限制一句话`。这句话的要求：三十到六十个字，点名变量，带一个最关键的数（引用脚本的），不带建议。
- 诊断不产生动作。发现需要查证的事（例如到仓日期、退货原因），指到清单里已有的「查证」「Listing 建议稿」动作；清单里没有就列为「清单外建议」。

## 七、不许做的

- 不报两个以上的核心限制，不用「综合来看多方面原因」收尾。
- 不自己重算节点的值。发现对不上（例如活动报告和搜索词报告花费差得多），指到 `口径核对`，让人先核数据。
- 不拿归因未满的那几天说转化率下降。
- 不在没有排名数据时说「广告带动了自然位」或「自然位掉了」。
- 不把时间上的重合说成因果。只有重合，就写「时间重合，证据弱」。
- 不在这里给调价、否词、换图的具体方案。
- 不因为用户觉得有问题就一定找出一个问题。`无明显限制` 是合法结论。

## 八、自查三句

1. 我只给了一个核心限制吗？它在七类之内吗？
2. 从 TACOS 到这个限制，中间每一层我都有数吗？没数的那层有没有写「缺」？
3. 我写了这个判断在什么情况下不成立吗？
