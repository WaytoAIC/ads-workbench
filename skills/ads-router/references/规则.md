# ads-router · 路由细则

## 一、五种状态怎么认

| 状态 | 认定依据（任一成立） | 第一顺位 |
|---|---|---|
| 没跑过 | 没有 `广告闭环/输出/数字.json`；或 `运行记录/runs.jsonl` 为空且输出目录是空的 | 不分析，先让人跑一圈 |
| 遇到问题 | 任务状态是「遇到问题」；`运行记录/runs.jsonl` 最后一行有失败步骤或 `problems` 不空；`广告闭环/输出/验证器.json` 有不通过项 | `ads-weekly-review` 的数据体检 |
| 待重跑 | 任务状态是「待处理」或页面显示「待重跑」；`参数.json` 的修改时间晚于 `广告闭环/输出/数字.json` | 提醒重跑，再按话路由 |
| 待审批 | 任务状态是「待核对」；有动作停在「待确认」 | 按话路由，结尾提醒待确认条数 |
| 到复盘日 | `参数.json` 的 `今天`（没有就用系统日期）不早于 `复盘日` | `ads-weekly-review` |

同时命中多种时的优先级：没跑过 > 遇到问题 > 到复盘日 > 待重跑 > 待审批。

没有任何一种命中（跑过、没问题、没到复盘日、动作都处理完了）：这是「平稳」，直接按话路由。

## 二、按话路由表

| 用户在问 | 主 skill | 常见配角 |
|---|---|---|
| 目标 TACOS 定多少、能花多少广告费、现在赚还是亏、预算给多少 | ads-profit-target | ads-path-decision |
| 为什么 TACOS 涨了、ACOS 高在哪、利润怎么掉了、单量怎么没上来、怎么突然卖多了 | ads-diagnose | ads-campaign-task |
| 这个活动留不留、哪些广告在白花钱、活动太多理不清、有没有重复投放、哪些广告能直接赚钱 | ads-campaign-task | ads-bid-budget |
| 搜索词报告怎么看、哪些词该否、哪些词该单独打、分组分错了 | ads-search-term | ads-bid-budget |
| 出价多少、竞价怎么调、要不要加预算、预算老花完、广告位加不加价 | ads-bid-budget | ads-campaign-task |
| 接下来主攻什么、先放量还是先降 TACOS、要不要调价、出一张决策表 | ads-path-decision | ads-profit-target、ads-diagnose |
| 跑一下本周、出周报、上周的动作有没有效、到复盘日了 | ads-weekly-review | ads-diagnose |
| 新品怎么推、上架第几周该做什么、推得是不是太快、新品能不能放量 | ads-launch | ads-profit-target |
| 主推哪个规格、规格之间抢流量、旺季怎么备、淡季广告停不停 | ads-variant-season | ads-bid-budget |

话里没有明确指向时，按 `拆解.核心限制.变量` 路由：

| 核心限制 | 主 skill |
|---|---|
| 库存 | 新品 → ads-launch；有多个规格 → ads-variant-season；否则 ads-bid-budget（预算和广告产品先收） |
| CPC | ads-bid-budget |
| CVR | ads-diagnose（先分清是 Listing、价格、评价还是断货规格），再 ads-search-term（是不是买错了词） |
| 广告销售额占比 | ads-campaign-task |
| 无效广告 | ads-campaign-task，再 ads-search-term |
| 利润空间 | ads-profit-target，再 ads-path-decision（多半落在调价或重构） |
| 无明显限制 | ads-path-decision（多半是增单） |

## 三、阶段分流

| `产品阶段` | 主线 | 说明 |
|---|---|---|
| 新品期 | ads-launch | 目标是把自然流量沉淀下来；TACOS 可以高于目标，但要有期限和损失边界。其余 skill 被叫到时要按新品的口径回答 |
| 放量期（旧写法：成长期） | 成熟链接主线 | 重点在 ads-profit-target（放量时允许亏、平本还是微利，要人定）和 ads-path-decision（多半是增单） |
| 维稳期（旧写法：成熟期） | 成熟链接主线 | 重点在 ads-diagnose、ads-campaign-task、ads-path-decision（多半是降耗） |
| 盈利期 | 成熟链接主线 | 重点在 ads-path-decision（先问优先利润额、利润率还是规模）和 ads-campaign-task（纯利型广告） |

有明显季节性的产品，不管哪个阶段，问到预算和目标时都带上 `ads-variant-season`。

## 四、三个 skill 怎么排

1. 前置（最多一个）：经营链上排在前面、还没做的那一环。
2. 主 skill（一个）：回答用户这次问的问题。
3. 落地（最多一个）：把结论变成动作的那一个，通常是 ads-bid-budget 或 ads-search-term。

前置和主 skill 是同一个时，只算一个。用户赶时间、只要一个答案时，只跑主 skill，把前置缺的那一环写进「还缺什么」。

## 五、用户话里的信息不够

只问一个问题，问最能缩小范围的那个：

- 不知道是哪个产品 → 「是哪个产品（数据目录）？」
- 不知道想要什么 → 「你现在最想改变的是哪一个：利润、单量，还是先弄清楚问题在哪？」
- 阶段没填 → 「这个产品现在按新品、成长还是成熟来管？」

不连问三个问题。问完一个，其余的按文件里现有的信息往下走。
