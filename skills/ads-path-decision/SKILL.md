# ads-path-decision · 选路径、出决策表

同一个「想多赚点」，背后可以是四件完全不同的事。先选定走哪一条，后面的动作才不会互相打架。你的工作是把四条路摆清楚、给出有依据的建议，然后把选中的那条写成一张能照着做、到日子能复盘的决策表。

共用规矩在 `../ads-shared/`：`分工与红线.md`（先读）、`公式与口径.md`、`输出格式.md`、`术语.md`。本 skill 的细则在 `references/规则.md`，输出模板在 `templates/输出.md`。

## 一、什么时候用，什么时候不用

用：

- 「这个链接接下来主攻什么」
- 「是先把量做上去，还是先把 TACOS 降下来」
- 「老链接利润卡住了，还有什么办法」
- 「要不要涨一点价」「要不要降价换自然单」
- 「给这个产品出一张决策表」
- 「按上次定的路走了两周没效果，换哪条」

不用：

- 账没算、目标没有：先 `ads-profit-target`。
- 不知道卡在哪：先 `ads-diagnose`。没有核心限制就选路，等于蒙。
- 新品期（头几周）：用 `ads-launch`。新品先解决有没有自然单，四条路径是给已经有稳定销量的链接用的。
- 路已经定了，问具体动作的数：`ads-bid-budget`、`ads-search-term`。
- 复盘某条路走得怎么样：`ads-weekly-review`（它会带着复盘结论回到这里的「后续选择」）。

## 二、先读什么

| 读什么 | 看哪些键 | 用来做什么 |
|---|---|---|
| `广告闭环/输出/经营.json` | `路径.候选`（每条的 `key`、`名`、`适用`、`理由`、`测算`）、`路径.脚本建议`、`路径.建议依据`；`决策表` 九栏骨架；`算账` 整段；`拆解.核心限制`；`任务`（各任务的花费与完成情况） | 主干 |
| `广告闭环/输出/AI补位.json` | `路径建议`（`选`、`理由`、`不选其他的理由`）、`决策表草稿`、`状态` | 上一次你写了什么 |
| `参数.json` | `产品阶段`、`目标ACOS`、`定价毛利率`、`目标广告后利润率`、`取舍项`、`复盘日`、`补货到仓周数` | 人已经定了什么 |
| `广告闭环/输出/选项.json` | 五组取舍项的 `名称`、`做什么`、`代价`、`已选`、`动作条数` | 路径落到这一圈出哪几组动作 |
| `广告闭环/输出/动作清单.json` | 按取舍项和类型的分布 | 决策表「执行方案」引用编号 |
| `广告闭环/输出/数字.json` | `四周`、`逐周`、`库存`、`异常` | 当前状态与库存闸 |
| `广告闭环/输出/读回状态.json`、`运行记录/runs.jsonl` | 上一圈人选了什么、处理了什么 | 路径有没有中途换 |
| `口径.json` | `复盘.观察天数`、`复盘.初查天数`、`复盘.决定天数`、`经营.示例ACOS降幅`、`经营.调价测算金额`、`经营.无效广告花费占比警戒`、`经营.广告销售额占比警戒`；待补键 `门槛.复盘下结论订单`（读不到只说方向） | 读测算、写验证标准和复盘时间 |

页面对应：路径和决策表显示在「原因」页；首要目标和取舍项由人在「设置」页定；动作在「行动 · 待你决定」。

拿不到时：

- 没有 `广告闭环/输出/经营.json`：让用户先跑一圈或运行 `python3 _脚本/weekly.py --dry-run`。在那之前可以把四条路径的含义讲清楚，但不给建议。
- `路径.候选` 里某条的 `测算` 字段是 `null` 带 `缺`：那一条写「缺某某，测算做不了」，不凭感觉补。
- 没有自然排名、搜索量数据：增单路径里「自然单从哪补」只能列方向，不能说哪个词有空间。要查得花钱，先说清。
- 人没定首要目标：见第四节第 2 步。

## 三、脚本算什么，你做什么

| 脚本算 | 你做 |
|---|---|
| 四条候选各自适不适用、理由、测算（现广告单、现自然单、目标结构等） | 把测算读成一句人话：走这条路意味着要多出多少广告单、多少自然单，或 ACOS 要降到多少 |
| 脚本建议（四条之一，或「先解决库存」） | 解释它；可以有不同看法，写进「AI 判断」 |
| 决策表骨架：九栏各一句，按脚本建议的路径写（首要目标栏写着「人定」） | 在骨架上细化，不改里面的数 |
| — | 给路径建议：选哪条、理由、不选其他三条的理由 |
| — | 细化决策表：把执行方案落到具体对象和动作编号，补测试范围，把验证标准写成到日子能对着数判断的话；人选的路径和脚本建议不同时，后六栏按人选的重写 |
| — | 检查每个动作答不答得出三问 |
| — | 首要目标：把选项摆出来，等人定 |

## 四、判断步骤

1. **过库存闸。** `路径.脚本建议` 是「先解决库存」，或 `异常` 里库存是最高级别：先说库存。货撑不到补货时，四条路都得让路，增单尤其不能谈。决策表照出，但「选择方向」写「先解决库存，之后再选」，执行方案指向保主力规格那组动作。
2. **确认首要目标。** 这是人定的栏。没定就问两句，只问这两句：
   - 现在最想改变的是什么：利润额、利润率，还是单量？
   - 能接受的 TACOS 是多少？（或：能接受单量掉多少？）
   人答了：复述成一句目标（例如「单量不掉的前提下把 TACOS 降到目标内」）。人没答：按脚本建议往下写，但「首要目标」栏写「（待你定）」，并说明换一个目标建议会怎么变。
   人既要立刻降 TACOS、又要马上放量、还不愿动价格：指出这三样同时要做不到，请他排先后。
3. **四条路逐条过。** 每条读 `适用` 和 `理由`，再对照 `references/规则.md` 第一节的适用条件和测算读法：
   - `增单`：脚本在「核心限制不是库存和利润空间、TACOS 没超目标」时标适用。测算告诉你目标之内广告还能多买多少单；其余的要靠自然单。
   - `降耗`：脚本在「TACOS 超目标，或核心限制是 CPC、CVR、无效广告、广告销售额占比，或无效花费占比过线」时标适用。三种做法：砍无效花费、提高自然单占比、降 ACOS。
   - `调价`：脚本在 TACOS 超目标时标适用，并给出每件提一个金额的利润率上限。它真正合适的场合更窄：自然单难再增、ACOS 也没多少可降，而价格有弹性。弹性脚本不知道，要试。
   - `重构`：脚本在「TACOS 高过定价毛利率，或广告销售额占比超过警戒」时标适用。意思是现有的赚钱方式可能不成立，要换一种价格与广告的搭配。
4. **选一条作为建议。** 标准只有四个：有证据、链路短、投入可控、容易复盘。几条都适用时，选这四样最占优的；说明其余几条为什么这次不选（是「不适用」还是「适用但排后面」）。脚本建议和你的建议不同时两个都摆出来。**最后一句是「走哪条要你定」。**
5. **选定路径下的具体抓手。** 一条路下面还有岔口，细则在 `references/规则.md` 第二节。例如增单：自然单从更大的词、更多的词、更高的位置、更多规格的有效位置里选一个最容易的；或者不靠自然单，靠降 ACOS 扩容，或放大纯利型广告。只选一到两个抓手。
6. **对上任务盘点。** 读 `任务`：降耗先动未达标的手段型广告；增单先看有没有纯利型候选。任务大多是 `未判定` 时，决策表的执行方案第一条就是「去广告活动页确认任务」，并提示 `ads-campaign-task`。
7. **对上取舍项。** 路径是方向，取舍项是这一圈让脚本出哪几组动作（`广告闭环/输出/选项.json`）。说明选定的路径需要哪几组、现在勾了哪几组、差在哪。勾不勾是人的事。
8. **写九栏决策表。** 栏目定义在 `../ads-shared/输出格式.md` 第五节。要求：
   - 当前状态、核心限制：照抄脚本。
   - 首要目标：人定的原话，或「（待你定）」。
   - 执行方案：具体到搜索词、规格、广告活动、价格或预算；清单里有的引用动作编号。
   - 投入边界：预算上限取 `算账.单品日预算`；测试范围写清动哪些、不动哪些；能承受的阶段损失要人确认。
   - 验证标准：一个能读回的数和方向，带上样本要求（`门槛.复盘下结论订单`）。
   - 复盘时间：初查和决定两个时点（`复盘.初查天数`、`复盘.决定天数`），和 `参数.json` 的 `复盘日` 对齐。
   - 后续选择：有效怎么放大，无效怎么撤回，撤回后换哪条路。
9. **逐个动作过三问。** 为什么做、预期改变什么、多久复盘。答不出的动作从执行方案里拿掉。
10. **提醒不要中途换目标。** 同一个动作可以服务不同目标。降 ACOS 省下来的钱：目标是增单就接着投出去，目标是降耗就留下。写清这一次属于哪种，免得做着做着变了。

## 五、常见情形

**情形 1：账在目标内、没有明显限制，盘点里有纯利型候选**

- 读到：`算账.判定` 在目标内且有余量；`拆解.核心限制.变量` 是无明显限制；`任务` 里有标了纯利型候选的活动。
- 判断：增单适用。三组抓手里，放大纯利型链路最短、最容易复盘。
- 怎么答：建议 `增单`，抓手选放大纯利型；写清每一步加多少由 `ads-bid-budget` 定、看「花得出去、有成交、ACOS 在线内」。
- 不要：同时铺开四个自然流量抓手。

**情形 2：超出目标，核心限制是无效广告**

- 读到：`算账.判定` 超出目标；未达标和未判定的活动占了不小的花费。
- 判断：降耗适用，先砍无效花费。
- 怎么答：建议 `降耗`；执行方案引用撤回类、否定类动作的编号；说明总单量可能略降、看利润；分步。
- 不要：承诺「不会掉单」。

**情形 3：已亏损，核心限制是利润空间**

- 读到：TACOS 高于定价毛利率；定价毛利率本身偏低；ACOS 已经没有多少下降空间。
- 判断：降耗救不回来。要动价格或换结构。
- 怎么答：摆出 `调价` 和 `重构` 两条，各自的账怎么算、怎么小步试、什么情况下撤回；说明这两条后果大，请人定。
- 不要：继续建议微调出价。

**情形 4：人还没定首要目标**

- 读到：`决策表.首要目标` 是「（人定）」；对话里也没说。
- 判断：不能替他填。
- 怎么答：问那两句；同时按脚本建议出一版，首要目标栏写「（待你定）」，并用一两句说明「如果目标换成另一种，建议会变成什么」。
- 不要：把脚本建议当成他的目标写进去。

**情形 5：库存亮红灯，用户问「怎么把量再做大」**

- 读到：`路径.脚本建议` 是先解决库存。
- 判断：这时候谈增单会让断货来得更快。
- 怎么答：先说库存；决策表的选择方向写「先解决库存，之后再选」；到仓日确认后再回来。
- 不要：照他的问题给增单方案。

**情形 6：上一条路走了两个周期，复盘判无效**

- 读到：`ads-weekly-review` 的结论；上一张决策表的「后续选择」。
- 判断：按当初写的撤回办法执行，再换路。
- 怎么答：先确认动作是不是到位了（没到位不算路径无效）；到位了，按后续选择撤回，再从四条里重新比。
- 不要：因为已经投入很久就建议再等等。

## 六、输出

- 按 `../ads-shared/输出格式.md`，加 `templates/输出.md` 的路径比较表和九栏决策表。
- 平时只在对话里回答。每周一圈时，由 `_脚本/llm.py` 写进 `广告闭环/输出/AI补位.json`：
  - `路径建议`：`选`（四条之一）、`理由`、`不选其他的理由`。不在四条里的值会被丢弃。
  - `决策表草稿`：`首要目标`、`执行方案`、`验证标准`、`复盘时间`。其中「首要目标」只是把选项写成一句话供人确认，以「（待你定）」开头；人在页面上定了之后以人的为准。
- 落盘的文字里不带新数字，引用的数都要在脚本产物里找得到。

## 七、不许做的

- 不替人选路径，不替人填首要目标。
- 不在库存有红灯时建议增单。
- 不在没有核心限制时给路径建议。
- 不同时推两条以上路径。
- 不把调价、重构说成「试试无妨」：这两条动的是价格，后果大，要写清怎么小步试、看什么数、什么情况下撤回。
- 不拿别的产品的打法当依据。「别人这样做成了」不是这个产品的证据。
- 不写没有验证标准和复盘时间的执行方案。
- 不因为一条路已经走了很久就建议继续。复盘说无效，就写怎么撤。

## 八、自查三句

1. 我给的路径在四条之内，并且写了不选其他三条的理由吗？
2. 首要目标是人的原话，还是我替他写的？替他写的有没有标「（待你定）」？
3. 决策表里每个动作，三问都答得出吗？验证标准是一个到日子能读回来的数吗？
