# 广告周检工作台 · 架构（工作台 + 技能包 + Agent + Harness）

一句话：**数字归脚本，判断归模型，拍板归人。** 流水线照旧算数；技能包告诉模型每一步读什么、判断什么、写到哪；Agent 是装了技能包、能被问、每周自己醒的那个壳；Harness 是把触发、口径、状态、护栏、评测串起来的那一圈。

## 一、目录约定（谁写哪里）

| 路径 | 是什么 | 写入方 |
|---|---|---|
| `口径.json` | 阈值与调幅的**唯一来源**（调价上限、点击门槛、复盘天数…）；流水线读它，技能包引用它 | 人改；脚本只读 |
| `参数.json` | 这一圈的输入：目标 ACOS、到仓周数、阶段、**定价毛利率、目标广告后利润率**、数据窗口 | 人（经工作台） |
| `ads.config.json` | Agent 与 Harness 的配置：Hermes 地址和 profile、模型通道、每周节奏、推送 | 人改 |
| `广告闭环/输出/数字.json` 等 | 流水线产物（事实、异常、动作清单、验证器） | `pipeline.py` / `render.py` |
| `广告闭环/输出/经营.json` | 经营核算：算账、拆解、广告任务、利润路径、决策表骨架 | `_脚本/biz.py`（确定性，不调模型） |
| `广告闭环/输出/归因.json` | 归因：每个问题的拆解表（是谁造成的）、每条分析的支持／反对／能解释多少／把握／还缺、每条对策主要靠哪条分析 | `_脚本/attribution.py`（确定性，不调模型） |
| `广告闭环/输入/人的判断.json` | 人对每条分析的判断和理由、人点了才存下的 Agent 备注（源头是状态库） | `工作台/app.py` |
| `广告闭环/输出/AI补位.json` | 模型写的文字：核心限制一句话、路径建议、任务标签草稿、搜索词补位、决策表草稿、周报草稿 | `_脚本/llm.py`（没接模型时写 `状态: skipped`） |
| `运行记录/runs.jsonl`、`运行记录/*.log`、`运行记录/周报-*.md`、`运行记录/sent.log` | 每周一圈的留痕 | `_脚本/weekly.py`、工作台 |
| `工作台.db` | 状态库：任务、运行、动作、行动卡、操作记录、**活动任务（人确认）** | 只有 `工作台/app.py` |
| `广告闭环/输入/活动任务.json` | 人确认过的活动任务的副本，给 `biz.py` 读：完成情况按人定的任务判（源头是状态库） | `工作台/app.py` |
| `agent/.env.local` | 本机的模型通道（不进仓）：直接写钥匙，或只写钥匙在哪个文件、叫什么名 | 人 |
| `skills/` | 技能包（MIT），装进 Claude Code / Codex / Hermes | 人维护 |
| `agent/` | Agent 定义：`SOUL.md`、`岗位卡.json`、`install_hermes.sh`、定时脚本 | 人维护 |
| `评测/` | 考卷与评分口径 | 人维护；`_脚本/eval.py` 跑 |

## 三、`AI补位.json` 的结构（`llm.py` 产出）

```json
{"状态": "ok | skipped | partial", "原因": "没接模型 / 超时 / …", "模型": "…", "通道": "…", "生成于": "…",
 "核心限制一句话": "…", "路径建议": {"选": "降耗", "理由": "…", "不选其他的理由": "…"},
 "任务标签": {"词组主干": {"任务": "纯利型", "理由": "…"}},
 "搜索词补位": {"some search term": "核心大词"},
 "决策表草稿": {"首要目标": "…", "执行方案": "…", "验证标准": "…", "复盘时间": "…"},
 "周报草稿": "…Markdown…"}
```
实际文件还带 `各项`（每一项的状态）、`丢弃`（校验时丢掉了什么、为什么）、`calls`（调用次数）。数字或口径在它写完之后变过（跑了新一圈、改了定价毛利率或目标利润率），工作台给它标「过期」，页面撤下旧文字，重跑补位后恢复。

规矩：模型只写文字和枚举，**不写新数字**；枚举值必须落在口径允许的集合里（任务六类、分组七类、路径四条），不在集合里的丢弃并记 `partial`；`llm.py` 校验后才落盘。页面上凡是来自这里的内容都标「Agent 写」。

## 四、字段分工（护栏）

| 谁写 | 写什么 |
|---|---|
| 人 | 目标（ACOS、定价毛利率、目标利润率、阶段、到仓周数）、对策取舍、每条动作通过/驳回及理由、活动任务的**确认**、决策表的「首要目标」、发到群 |
| 脚本 | 一切数字、异常判定、动作清单、验证器、经营核算 |
| Agent（模型） | 核心限制一句话、路径建议、任务标签**草稿**、搜索词补位、决策表草稿、周报草稿 |

硬规矩：Agent 不审批、不改目标、不上传后台、不自己发群；群消息只出草稿，人在页面点了才发；动钱的动作停在「待确认」；花钱的取数先说清调用几次。
每周一圈默认不往群里推任何东西；`ads.config.json` 的 `weekly.推送` 改成 `"摘要"` 且设了 Webhook，才推结尾那段运行摘要，周报正文仍然要人点。

## 四点五、数据怎么进来

两个来路，落到同一个「我的数据」文件夹、同一种格式，后面都走 `_脚本/import_my_data.py`：

- **从接口拉**（`_脚本/ads_report.py`）：四份按天的 SP 报表（搜索词 `spSearchTerm`、广告产品 `spAdvertisedProduct`、活动 `spCampaigns`、同一种报表按广告位汇总的一份，走 `POST /reporting/reports` → 问进度 → 下载）＋ 四类对象的结构（`/adsApi/v1/query/{campaigns|adGroups|targets|ads}`）→ 广告侧九张表。有广告位那张，流水线才出「下调／上调广告位加价」。报表没生成完先停并记下任务编号，下次接着取。
- **手工导**：照 `数据格式.md` 从后台导。人自己放的文件，接口不覆盖。
- 生意侧（件数、销售额、库存、毛利）不在广告接口里，只能人填。
- 新版接口能做什么、每条的依据：`Ads接口文档.json`（页面「广告接口 → 新版文档」）。现在用的报表接口 2027-06-30 停止出数，要迁到 `/adsApi/v1/create/reports`。

## 五、接口（`工作台/app.py`）

现有：`/api/state`、`/api/run`、`/api/inputs`、`/api/action/<no>`、`/api/bulk`、`/api/reset`、`/api/progress`、`/api/export.csv`。
新增：
- `GET /api/health`：工作台、Hermes 网关、Agent 路由、模型通道各自通不通。
- `POST /api/agent`：`{messages, context}` → 转给 Hermes `/p/<profile>/v1/chat/completions`，流式原样返回；服务密钥只在服务端从 profile 的 `.env` 读。
- `POST /api/ai-fill`：重跑一次模型补位（只有老板、广告运营能点）。
- `POST /api/task`：`{campaign, task}` 人确认或改一个活动的任务（写状态库，写入方＝当前身份；随后重算经营核算）。
- `POST /api/inputs` 另收 `margin`、`target_profit`：写 `参数.json`，只重算经营核算，不出新版本、不动动作。
- `POST /api/ads/pull`（要 `confirm:true`，会花紫鸟积分）：后台从广告接口拉报表和结构，写到本机配置的数据目录；结果只留个数，在 `运行记录/ads-api-报表.json`。
- `GET /api/ads/preview?status=&types=`：把广告类动作翻成 Amazon Ads API 请求，只摆出来不发。`POST /api/ads/check`（要 `confirm:true`，会花紫鸟积分）连一次并只记个数。`POST /api/ads/execute`：`{no, confirm_text}` 发一条，开关没开、演示数据、没写确认的话都会被拦；成功并回读后动作标「已执行」。
- `POST /api/verdict`：`{node, verdict, reason}` 人对一条分析下判断（认同／不认同／先查再说；后两种必须带理由）。
- `POST /api/hypothesis`：`{text, dry:true}` 只核对 Agent 写的「新分析」块，返回拆好的草稿、不能采纳的原因、提醒；`{text, confirm:true}` 人点了才采纳（存状态库，读状态时并进树和归因）；`{delete:id}` 从树上拿掉。
- `POST /api/note`：`{node, text, confirm:true}` 人点了才把 Agent 的回答存到节点；`{delete:id}` 删。
- `POST /api/agent` 另收 `object:{type,id,label}`：页面把正在看的节点结构化地带过去，后端告诉 Agent 去哪读它的材料。
- `POST /api/post-to-group`：`{text, confirm:true}` 人点了才发（走 `FEISHU_WEBHOOK`），写 `运行记录/sent.log`。
- `/api/state` 增加：`biz`（经营.json）、`ai`（AI补位.json）、`tasks`（人确认过的任务）、`runlog`（runs.jsonl 末 12 条）、`weekly`（最新周报草稿）、`jobcard`、`skills`、`harness`（七个部件的状态）、`koujing`、`agentCfg`。

模型通道怎么找：环境变量 `ADS_LLM_*` → `agent/.env.local` → `ads.config.json` 的 `llm` 段 →（开着时）本机 Hermes。问 Agent 先走 Hermes 上的 profile（能读文件、能用技能），没接上才走直连模型（只看得到这一圈脚本算好的要点）。

## 六、每周一圈（`_脚本/weekly.py`，Harness 的主循环）

`读回状态 → 数据体检 → 跑一圈（工作台的 Loop：算数、出动作、验证、写状态）→ 经营核算 → 模型补位 → 自检 → 起草周报 → 留痕`
每步失败只记进 `problems` 不拦后面；这一圈没重跑、数字没变时，模型补位沿用上次的，不重复调用；`--dry-run` 不写状态库、不跑流水线、不调模型、不写周报文件；结束追加一行到 `运行记录/runs.jsonl`（时间、触发、各步 ok/耗时、动作数、待审批数、模型调用次数、problems）；有失败退出码 1，缺输入退出码 2。

## 七、Harness 七个部件各落在哪

| 部件 | 落在哪 |
|---|---|
| 触发 | 页面「跑一圈」；Hermes 定时（每周一 9 点跑 `weekly.py`）；问 Agent |
| 配方 | `skills/`、`口径.json` |
| 上下文 | `数字.json`、`经营.json`、状态库里的驳回理由和已确认动作、`运行记录/` |
| 工具 | `_脚本/*.py`（只读数据）、Hermes 上已装的取数技能 |
| 护栏 | 状态机、权限表、验证器、字段分工、群消息人闸 |
| 状态 | `工作台.db`、`广告闭环/输出/` |
| 评估 | `评测/` + `_脚本/eval.py`；每条动作的「怎么算成功」和复盘日 |
