# 评测：这套 Harness 还靠不靠谱

改了规则、口径、提示词、模型之后，跑一遍考卷，看哪条断言变了。**数字和动作归脚本，所以能硬判；文字归模型，所以按口径打分。**

```bash
python3 _脚本/eval.py                    # 确定性部分：不调模型，十几秒
python3 _脚本/eval.py --case 到仓1周      # 只跑一个案例
python3 _脚本/eval.py --llm --times 3     # 再把模型补位每个案例跑 3 次，看枚举稳不稳（要花模型调用，开跑前会先报次数）
python3 _脚本/eval.py --keep              # 留着临时副本，事后翻看每个案例的产物
```

每个案例都在临时副本上跑：拷一份数据目录 → 回到基线 → 改几个输入 → 跑 `weekly.py --no-llm`（流水线＋经营核算）→ 核对断言。仓库本身的 `工作台.db` 和产物不动，不推送。
结果写 `评测/结果-<日期>.json`（不进仓），同时打一段 Markdown：一张「案例 × 断言」的通过表、总分、失败和跳过的明细。有断言失败退出码 1。

## 考卷怎么加

`评测/考卷.json` 的 `案例` 里加一段：

```json
{"id": "短名字", "说明": "这个状态想考什么",
 "改参数": {"补货到仓周数": 1},
 "跑完流水线后": [{"删键": ["广告闭环/输出/数字.json", "活动表"]}],
 "期望": {"退出码": 0, "动作数": 56, "验证器全过": true},
 "期望的依据": "这些数为什么该是这样（实测值，还是契约推出来的）",
 "模型看点": ["这个状态下模型最容易写错什么"]}
```

- `改参数`：写进副本的 `参数.json`；值写 `null` 表示删掉这个键（比如删掉「补货到仓周数」考缺输入，期望 `"退出码": 2`）。
- `跑完流水线后`：流水线跑完、经营核算重算之前动一下产物，用来考「缺数据时不崩、不拿 0 当数」。现在只有 `删键`：`[文件, 键, 子键…]`。
- `期望` 能写的断言：

| 断言 | 值 | 查什么 |
|---|---|---|
| `退出码` | 0 / 1 / 2 | `weekly.py` 的退出码 |
| `动作数` | 整数 | 这一版动作清单的条数 |
| `有动作类型` / `没有动作类型` | 类型名列表 | 这一版动作里有没有这些类型 |
| `验证器全过` | true | `验证器.json` 每项都通过 |
| `动作全部待确认` | true | 新动作没有一条被 Agent 自己点过 |
| `TACOS恒等式` | true | `数字.json`：四周广告费 ÷ 销售额 ＝ TACOS |
| `经营恒等式` | true | `经营.json`：TACOS＝ACOS×广告销售额占比；目标 TACOS＝定价毛利率−目标广告后利润率；余量＝目标−当前；当前 TACOS 和 `数字.json` 对得上 |
| `任务枚举合法` / `路径枚举合法` / `核心限制枚举合法` | true | 枚举值都在契约允许的集合里 |
| `判定`、`核心限制变量`、`脚本建议` | 一个值或几个值（任一即可） | 经营核算的三个结论 |
| `核心限制变量不是`、`脚本建议不是` | 值列表 | 不该出现的结论 |
| `经营不崩`、`缺数有标注` | true | 缺数据时 `经营.json` 仍是合法 JSON，缺的地方有「缺」或「错误」，没有硬给结论 |

依赖 `经营.json` 的断言，在 `_脚本/biz.py` 还没产出它时标「跳过：经营.json 不存在」，不算失败。
要加新的断言种类：在 `_脚本/eval.py` 的 `judge()` 里加一个分支，返回（通过/失败/跳过，一句说明）。

## 分数怎么读

- **总分＝通过 ÷（通过＋失败）**，跳过的不计分。演示数据上应该是满分；不是满分就先看「失败」那一节每条的「实际 vs 期望」。
- **跳过多**不是好事也不是坏事：说明有部件没就位（比如没有 `biz.py`），那部分没被考到，别当成通过。
- **`--llm` 的三个数**：
  - 一致率＝同一份输入跑几次，枚举项（路径选哪条、每个活动的任务、每个搜索词的分组）几次都一样的比例。温度已经是 0，低于 90% 说明提示词有歧义或材料不够，先改提示词，别急着换模型。
  - 被校验丢弃＝枚举不合法或编了数字被 `llm.py` 拦下的条数。应该接近 0；多了说明模型在硬编，页面上看到的补位会缺一块。
  - 状态里出现 `skipped`＝通道没通或材料缺，看「没出枚举项的原因」。
- `--llm` 用的模型通道和 `weekly.py` 是同一套解析（环境变量 `ADS_LLM_*` → `ads.config.json` → 本机 Hermes）；没接模型时会说一声，只跑确定性部分。
- **文字质量不自动判**。拿考卷顶部的「模型评分口径」五条和各案例的「模型看点」，对着 `--keep` 留下的副本里的 `广告闭环/输出/AI补位.json` 逐条打分；也可以把这两样连同 `经营.json` 交给另一个模型打分。

## 什么情况算回归

1. **没改规则，分数掉了**：一定是回归。先查是谁动了 `pipeline.py` / `biz.py` / `口径.json`。
2. **`动作数` 变了**：改了动作规则或 `口径.json` 的阈值，动作数变是预期的——确认新动作清单是你要的，再把考卷里的数改成新值，并在「期望的依据」里写一句为什么变。没改规则却变了，是回归。
3. **`验证器全过`、`动作全部待确认`、三条恒等式、枚举合法**：这几条是护栏，任何时候挂了都是回归，不能靠改考卷过。
4. **`核心限制变量` / `脚本建议` / `判定` 变了**：改了经营核算的判定顺序或阈值才会变。变了要让定口径的人看过再改考卷。
5. **模型部分**：同一个模型、同一份考卷，一致率比上一次的 `结果-*.json` 掉 10 个点以上，或丢弃条数明显变多，算回归；换模型后第一次跑的结果当新基线。

演示数据本身换了（重新脱敏、换了窗口），所有实测类的期望都要重新定基线：跑一次，人看过产物没问题，再把数写回考卷。
